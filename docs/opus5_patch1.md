# Critical

## C1 — 完全接受，这是最严重的一条

评审是对的，而且指出了一个我犯得很低级的错误：**我把 Verlet buffer 的判据写成了瞬时形式。** GROMACS 的 buffer 之所以由 `nstlist` 整个间隔的漂移估计决定，正是因为这个问题。我写 `max|x − x_ref| > skin/2` 时脑子里是"每步检查"，但 graph 化之后检查频率降到每 K 步，判据的语义就变了 —— 而我没有跟着改。

它的数值估算我复核了一遍，量级对：300 K 下氧原子单分量弹道漂移 $\sigma \approx 0.039$ nm/100 fs，而 $R \times N \approx 2.9 \times 10^6$ 个原子·副本的系综里，$5\sigma$ 尾部是常态事件（$5\sigma$ 单边概率 $\approx 3\times10^{-7}$，乘以 $2.9\times10^6$ ≈ 每窗口 1 个粒子）。**所以这不是稀有事件，是每个窗口都会发生若干次。** 比评审说的更糟。

更要命的是评审指出的第三点：**M2（`graph_replay(K) ≡ K × single_step()`）测不到这个 bug**，因为两侧用同一份失效列表，结果一致地错。这个 gate 给了我虚假的安全感。

### 采纳的方案（三层，全部要）

**① skin 预算显式分解**

$$\text{skin} = \underbrace{2 \times d_{\text{thresh}}}_{\text{检查阈值}} + \underbrace{s_{\text{window}}(K, T, \text{最重要的是尾部})}_{\text{窗口安全余量}}$$

$s_{\text{window}}$ 由 K 步内**最大位移分布的经验上界**定，不是 $1\sigma$ 或 $2\sigma$，而是取实测分布的 $\max$ 加 50% 余量。初始值：$K=50$、skin $= 0.25$ nm 下，$d_{\text{thresh}} = 0.05$ nm，$s_{\text{window}} = 0.15$ nm。这会让 list 比原设计大约 30%，构建更频繁 —— **这是必须付的成本，我之前的 0.25 nm 是拍的，现在它有推导了。**

**② 窗口内每步 max-displacement 归约 + device flag（关键补丁）**

积分 kernel 里顺路做一次 $\max_{a,r} |x - x_{\text{ref}}|$ 的 block 归约，写一个 device 端 int32 flag。这几乎免费（已经在读写 $x$）。重放结束后 host 检查 flag：

```
graph_replay(K)
if device_flag_triggered:
    → 该窗口作废，回滚到窗口起点 checkpoint，缩短 K 后重跑
    → 记录事件，用于自动调整 K 与 s_window
```

**"作废重来"要求窗口起点有 checkpoint** —— 这是新的显存与拷贝成本（$x, v$ 各一份，276 MB，可接受），也顺带解决了 m2 提的 checkpoint 问题。而且它让 flag 触发从"静默错误"变成"性能事件"：不影响正确性，只影响吞吐。

**③ 新增断言（补 M2 的漏）**

| ID | 断言 |
|---|---|
| **M13** | 构造窗口中段必然触发重建的初始条件（人为压低 skin），断言 flag 被触发、窗口被作废、且最终轨迹 $\equiv$ 每步检查的参考实现 |
| **M14** | 关闭安全机制运行同一体系，断言与开启时的力出现可检测差异（**证明这个机制在防真东西**，而不是永不触发的死代码） |

M14 这条是评审精神的延伸：**一个从不触发的安全检查和没有安全检查是等价的**，必须有测试证明它会触发。

## C2 — 接受问题，但选择的方案与评审的两个选项都不同

评审是对的，而且我查了 cuFFT 文档确认了它的前提：**cuFFT 的结果只在 plan 输入参数保持不变时才是位级可复现的**[ref:19,23]，而 **batch size 正是 plan 参数**。所以 batch-48 与 batch-1 之间无位级保证，M1 与 §5.1 确实不可同时满足。这个矛盾是实打实的。

评审给了两个选项：(a) 逐副本 plan 保位级；(b) M1 分层，倒空间放宽到 $10^{-12}$。

**我选 (b)，但要把它写得比评审建议的更严格**，因为 (a) 的代价我认为不可接受 —— 48 次单路 $128^3$ FFT 相对一次批量 FFT，效率损失可能到 3–5 倍，而 PME 是主导成本，这等于放弃批量设计的核心收益。

### M1 分层的精确形式

| ID | 范围 | 容差 |
|---|---|---|
| **M1a** | 直空间非键 + 键合项 + 约束 + 积分 + $\partial U/\partial\lambda$ 的对应部分 | **位级，零容差** |
| **M1b** | PME 倒空间能量与力 | rel $< 10^{-12}$ |
| **M1c** | 总能量、总力（含倒空间） | rel $< 10^{-12}$ |

**为什么 $10^{-12}$ 的放宽不污染下游**（这是评审要求说明的，我认为必须写清）：

1. **A1 的 $10^{-10}$、A2 的 $10^{-9}$、M7 的 $10^{-6}$ 都比 $10^{-12}$ 宽 2–6 个数量级** → 上游放宽不改变任何现有 gate 的判定
2. **$u_{kn}$ 的物理意义容差**：MBAR 对 $u_{kn}$ 的敏感度是 $O(k_BT)$ 量级，$10^{-12}$ 相对误差在 $u \sim 10^5\, k_BT$ 时是 $10^{-7}\,k_BT$，比统计误差低 5 个数量级
3. **但确定性叙事的核心用途被保住了**：M3（与 tile/block 无关）、M4（与 R 无关）、M6（与原子序无关）**在固定 plan 下仍然位级成立**，因为同一个 plan 的重复执行是位级可复现的[ref:19]。也就是说 **agent 的内核优化搜索仍有零方差守门人** —— 这是位级确定性最重要的用途，它不受影响

4. **新增约束**：cuFFT plan 参数（batch、尺寸、precision、layout）**纳入 run manifest 并哈希**。plan 参数变化视为语义变更，需重跑 M1b 基线。这把评审说的"埋在地基里的第三方库行为假设"变成了显式记录的配置。

**另加一条隔离测试**：

| ID | 断言 |
|---|---|
| **M15** | 同一 plan 重复执行 → PME 倒空间位级相同（验证 cuFFT 在固定 plan 下的确定性前提，而不是假设它） |

## C3 — 完全接受，而且这条评审给出的算法比我原来想的更好

我必须承认：**我写"3–5×"的时候心里只算了直空间。** 评审说得对，倒空间是 $u_{kn}$ 的主导成本，朴素实现是每构象 48 次铺展 + 48 次 FFT，$3\text{–}5\times$ 变成 $20\text{–}40\times$，这句性能主张是错的。

而它给的救法是正确且优雅的，我完整采纳。展开写清（评审提到"必须一起进同一个推导"，这点尤其对）：

### $u_{kn}$ 倒空间的二次型展开

电荷线性插值 $q_i(\lambda) = q_i^{(0)} + \lambda \Delta q_i$，则结构因子线性：$\rho_\lambda(\mathbf{k}) = \rho_0(\mathbf{k}) + \lambda\,\Delta\rho(\mathbf{k})$，于是

$$E_{\text{recip}}(\lambda) = \underbrace{\sum_{\mathbf k} S(\mathbf k)|\rho_0|^2}_{A} + 2\lambda\underbrace{\mathrm{Re}\sum_{\mathbf k} S(\mathbf k)\,\rho_0^*\Delta\rho}_{B} + \lambda^2\underbrace{\sum_{\mathbf k} S(\mathbf k)|\Delta\rho|^2}_{C}$$

**每构象只需 2 次电荷铺展 + 2 次 forward FFT + 3 次网格归约**，之后全部 48 个 λ 的 $E_{\text{recip}}$ 与 $\partial E/\partial\lambda = 2B + 2\lambda C$ 都是解析求值。

**三处必须同一个推导**（这是评审最重要的补充，也正撞在雷区 #1 的案发现场）：

$$E_{\text{self}}(\lambda) = -\frac{\alpha}{\sqrt\pi}\sum_i q_i(\lambda)^2 \quad\Rightarrow\quad \text{也是 } \lambda \text{ 的二次型}$$

$$E_{\text{excl}}(\lambda) = -\sum_{(i,j)\in\text{excl}} q_i(\lambda)q_j(\lambda)\frac{\mathrm{erf}(\alpha r_{ij})}{r_{ij}} \quad\Rightarrow\quad \text{同样二次型}$$

所以三处的系数 $(A, B, C)$ **必须在同一份代码里、用同一个 $\Delta q$ 向量、一次性算出来**，绝不能分三处独立实现 —— 这正是雷区 #1/#2 的根本成因。我把这条写成硬性实现约束：**三项共享同一个 `QuadraticLambdaExpansion` 结构体，任何一处单独求值视为规格违反。**

**多分量情况**：$C$ 个电荷微扰分量时是 $C(C+1)/2$ 个交叉项，铺展次数 $C+1$，FFT 次数 $C+1$。RBFE 里 $C$ 通常是 1–2，所以成本仍在 $3\text{–}5\times$ 内。**但要在 spec 里写明成本随 $C$ 的标度**，不能让 $C$ 大时静默变慢。

**新增断言**：

| ID | 断言 |
|---|---|
| **M16** | 二次型展开求值的 $E_{\text{recip}}(\lambda)$ $\equiv$ 逐 λ 朴素 FFT 求值，全部 48 个 λ，rel $< 10^{-12}$ |
| **M17** | 展开的 $\partial E/\partial\lambda = 2B + 2\lambda C$ $\equiv$ 中心差分（与 M-d 共用 harness） |

M16 是这条修改的关键 gate —— 朴素实现虽慢但简单，作为 oracle 保留在测试路径里。

## C4 — 接受，且我承认这是"修辞冒充数据"

评审的算术是对的：$30\text{–}65\%$ 的时间移除对应 $1.4\text{–}2.9\times$ 上限，而我写的 5–10× 缺口全压在未量化的 occupancy 上。**M2 的 <4× red flag 这条线在当前状态下不可证伪** —— 达不到时我无法区分"批量设计错了"和"基线本来就饱和"。这个批评我接受得毫无保留。

### E0 扩展为 E0a/E0b/E0c

| 实验 | 内容 | 决定什么 |
|---|---|---|
| **E0a** | OpenMM 60k 体系 `mixed` vs `double` 的 ns/day（排除 JIT、预热，多次取中位数） | 单精度路径要不要维护 |
| **E0b** | **单副本 fp64 的 Nsight Compute 剖析**：achieved occupancy、SM 利用率、memory throughput、各 kernel 的 stall reason、kernel 间空隙占比 | **把"occupancy 改善"变成带数字的假设** |
| **E0c** | 人为改变问题规模（$N$ = 5k / 20k / 60k），看单副本吞吐随 $N$ 的标度是否线性 —— 若小 $N$ 时吞吐不随 $N$ 下降，证明存在未饱和头寸 | 批量红利的上界估计 |

**M2 验收标准改为两段式**：

$$\text{预期加速} = \underbrace{f_{\text{amortize}}}_{\text{E0 前三项实测}} \times \underbrace{f_{\text{occupancy}}}_{\text{E0b/E0c 推导}}$$

**先由 E0 算出一个带区间的预测值，M2 验收对照的是这个预测值而非拍出来的 5×。** 若 E0b 显示单副本已达 70%+ occupancy，那么批量红利的现实上限就是 $\sim2\times$，M2 的目标应当据此下调 —— **而且那种情况下整个"批量副本"设计的价值需要重新评估**，这是应该在 M0 阶段就知道、而不是 M2 才发现的事。

这条实际上把 E0 从"精度决策实验"升级成了"架构决策实验"。评审的这个判断很有价值。

## M-c — 完全接受，这是个真实的正确性漏洞

我漏掉了整个 LJ 侧，而评审指出的关键点是：**OpenMM 的 `useDispersionCorrection` 默认开启且随 λ 变** —— 被 decouple 的原子对尾部积分有贡献。这会让 A1 的 $10^{-10}$ 对不上，且给 $\Delta G$ 带来系统性偏移。溶剂化自由能对尾部修正敏感是已知结果，这一项漏掉是真错。

### 新增 §5.3「LJ 侧规格」

必须写死：
- cutoff 值（建议 1.0 nm）
- **switch 函数**：有/无，若有则形式与 switching distance
- **长程处理**：解析尾部修正 vs LJPME（**建议：解析尾部修正，因为 LJPME 会让 C3 的二次型展开复杂化 —— LJ 的 $\epsilon$ 混合是几何平均，不是线性，倒空间无法二次型展开**）
- **尾部修正的 λ 依赖公式**：$E_{\text{disp}}(\lambda) = -\frac{2\pi N^2}{3V}\langle C_6(\lambda)\rangle\, r_c^{-3}$，其中 $\langle C_6(\lambda)\rangle$ 对所有对求平均且含 λ 缩放的 $\epsilon, \sigma$
- A1/A2 断言必须**单独覆盖**尾部修正项（不能混在总能量里，否则它的相对贡献太小会被淹没）

这一条顺带影响 §6.4：**尾部修正含 $1/V$，所以 NVT 固定体积的选择会通过尾部修正影响 $\Delta G$** —— 与 M-e 联动。

## M-d — 完全接受，这是最便宜的高价值补丁

评审指出的漏洞是真的：**自动微分的接线错误可以穿过全部现有 gate**。M9 只查端点、A3 只查积分后的 $\Delta G$、A2 只查能量。一个 `∂θ/∂λ` 漏乘或 λ 分量错位，如果恰好在端点为零、且总 $\Delta G$ 碰巧对（例如系统性偏差被 TI 积分抵消），就完全隐身。

### 新增 A6：中心差分 oracle

$$\frac{\partial U}{\partial \lambda_i} \approx \frac{U(\boldsymbol\lambda + \delta \mathbf e_i) - U(\boldsymbol\lambda - \delta \mathbf e_i)}{2\delta}$$

- **逐 λ 分量**断言，不只查总和
- fp64 下 $\delta \sim 10^{-5}$ 可达 rel $10^{-6}$ 一致性
- 在**多个 λ 中间点**测（不只端点）—— 端点常常是软核的退化点，最不容易暴露 bug
- 不需要新内核，ingest 层即可
- 与 M17 共用 harness

**另外采纳评审的延伸建议**：雷区 #12 的注入测试从"标量能量"扩展到"$\partial U/\partial\lambda$ 向量 + $u_{kl}$ 矩阵的完整索引"，因为索引错位在标量上更容易碰巧对。

## M-e — 接受，且这一条与我们上轮关于 NPT 的讨论直接联动

评审问的三个问题我确实没定义。补上：

### 预平衡协议（写死）

```
阶段 1  能量最小化                     R=1，λ=0
阶段 2  NVT 升温 (50 ps)               R=1，λ=0
阶段 3  NPT 预平衡 (500 ps)            R=48，全 λ 并行，每副本独立 MC barostat
                                       ← 各 λ 独立得到 ⟨V_λ⟩
阶段 4  取 V_prod                      RBFE: 全 λ 的 ⟨V_λ⟩ 平均（单体积）
                                       ABFE: per-replica ⟨V_λ⟩（分段恒容）
阶段 5  NVT 生产                       R=48，V 固定
```

阶段 3 的每副本独立 barostat 是必要的 —— 这样才能拿到 $\langle V_\lambda\rangle$ 的 λ 依赖。它在预平衡阶段，不受 graph 约束，所以成本可接受。

### 「单体积近似」登记为条件性成立知识（新雷区 #13）

$$\text{适用条件：} \quad \frac{\Delta V}{V} \lesssim 10^{-4} \;\text{且}\; \Delta q_{\text{net}} = 0$$

**不成立的情形**（必须在 ingest 阶段检测并警告/拒绝）：
- **净电荷改变的微扰** —— 与雷区 #3/#4 联动，$\Delta V$ 可达 $10^{-3}$ 量级
- **ABFE**（配体完全解耦，$\Delta V \sim$ 配体偏摩尔体积，200–400 Å³）
- **大体积配体或有明显构象变化的微扰**

而且因为 M-c，**尾部修正含 $1/V$**，单体积近似会通过尾部修正引入 λ 无关的常数偏移（无害）+ 若 $\langle V_\lambda\rangle$ 差异大则引入 λ 依赖偏移（有害）。这个耦合要写进雷区 #13 的说明。

# 我对总体判断的回应

评审的三条"接缝"诊断我完全同意，而且我想补一句它没说但我认为是根因的东西：

**这三处接缝有一个共同结构 —— 都是"我在设计 A 时定的参数/断言，在引入 B 之后语义变了，但我没回头改 A"。**

- C1：skin 判据是"每步检查"时代定的，graph 化后没改
- C2：M1 位级是"自己写的内核"时代定的，引入 cuFFT 后没改
- C3：$3\text{–}5\times$ 是想着直空间时算的，PME 进来后没改
- C4：$5\text{–}10\times$ 是感觉出来的，从没有对应任何测量

所以这不是四个独立错误，是**一个流程缺陷的四次显形**：spec 是增量写的，但没有"引入新机制时回查所有既有量化断言"的步骤。

### 对流程的修改（我认为这比修 C1–C4 更重要）

在 spec 里新增一节 **§14「量化断言溯源表」**，每一个数字都必须标注：

| 数字 | 出处 | 依赖哪些机制 | 谁引入的变更会使其失效 |
|---|---|---|---|
| skin = 0.25 nm | ~~拍的~~ → K 步漂移分布实测 | graph 的 K、温度、最重原子质量 | 改 K、改 timestep、改 HMR |
| $u_{kn}$ 成本 3–5× | C3 二次型展开推导 | 电荷线性插值、$C$ 分量数 | 引入非线性电荷调度、LJPME |
| 批量加速 5–10× | ~~感觉~~ → E0b/E0c 实测推导 | 单副本 occupancy | 换卡、换 $N$、换精度 |
| M1 位级 | 定点累加 + 固定 plan | cuFFT plan 参数 | 改 batch、改网格尺寸 |

**规则：任何引入新机制的变更，必须遍历此表并声明每一行是否受影响。** 这正是 C1–C4 会被自动捕获的机制。

# 修订后的启动顺序

C1–C4 的处置都必须在 M0 启动**前**写回 spec，其中：

1. **E0a/E0b/E0c 优先级最高** —— C4 的结论可能推翻整个批量架构的价值假设，这是必须最先知道的
2. **§4.6 炼金术完整解析定义 + §5.3 LJ 侧规格**（M-b/M-c/m7）—— 这是 A1/A2 能否成立的前提，M0 的验收依赖它
3. **C3 的二次型展开推导**（含自能/排除三项统一）—— 写进 spec 正文，朴素实现作为 M16 的 oracle 保留
4. **C1 的三层机制 + C2 的 M1 分层** —— 修改 §5.2/§7/§11.2
5. **§14 溯源表** —— 建立后回填所有既有数字

M-a/M-e 与全部 minor 一句话到一小节即可，同批改完。

一个我想反问评审的点，也是唯一一处我认为它可能低估了严重性的地方：

**C2 的方案 (b) 里，我保住的是"固定 plan 下的可复现性"，但 M4（结果与副本数 R 无关）在含 PME 时其实无法保住位级** —— 因为 R 变了 batch 就变了，plan 就变了。所以 M4 也要分层成 M4a（直空间位级）/ M4b（含倒空间，$10^{-12}$）。评审只指出了 M1 的矛盾，但同一个矛盾对 M4 同样成立，而 M4 是我用来验证"批量设计没引入 R 相关 bug"的主力 gate。这条要一起改，否则 M4 会在第一次跑 $R=1$ vs $R=48$ 对比时就红，然后被误诊为批量 bug。
