# 第一部分：先报告坏消息 —— 我按 B3 做了 roofline，结论比 C4 更糟

评审要求 bottom-up 账，我先算了，因为它会改变后面很多条的处置。

**直空间对数**：60k 原子，水密度 ~100 原子/nm³，cutoff 1.0 nm + skin 0.25 nm ⇒ 列表半径 1.25 nm

$$N_{\text{pair/atom}} \approx \tfrac{4}{3}\pi (1.25)^3 \times 100 \approx 818 \;\Rightarrow\; \text{半列表} \approx 409$$

$$N_{\text{pair}} = 60000 \times 409 \times 48 \approx 1.18\times 10^9 \ \text{对/步}$$

**每对 fp64 成本**：LJ + Ewald 实空间（含 `erfc` 或查表）+ 软核分支 ≈ 50–70 FLOP，取 60

$$\text{FLOP/步} \approx 7.1\times10^{10} \quad\Rightarrow\quad \frac{7.1\times10^{10}}{9.7\times10^{12}} \approx 7.3\ \text{ms/步（理想）}$$

实际按 40–50% of peak ⇒ **15–18 ms/步**。而 §10 的靶子（每副本 30–70 ns/day @ 2 fs）反推是 2.5–5.8 ms/步。

## 三个直接结论

**① §7 的"数百微秒"是错的，量级差 30 倍。** 评审 B3 完全正确。而且方向是我原来那个数**过于乐观**。

**② launch 开销摊薄这条红利基本不存在。** 单步 15 ms，数十个 kernel × 5–10 μs = 0.2–0.5 ms，占 **1.5–3%**，不是我写的 10–30%。**CUDA Graph 的价值被我高估了一个数量级。** 它仍然值得做（免费、无风险），但它不能是性能叙事的支柱。

**③ 更严重的：直空间在 fp64 下是计算受限的，且已接近饱和。**

$1.18\times10^9$ 对/步意味着 108 个 SM × 64 fp64 单元 = 6912 个 fp64 lane 全程有活干。这里**没有 occupancy 头寸可捡**。而 C4 的 5–10× 全部押在 occupancy 上。

所以我必须承认：**M2 的 5× 验收线极可能不可达，而且不是因为实现不好，是因为它从一开始就没有物理依据。** 修正后的现实预期：

| 红利来源 | 修正后估计 |
|---|---|
| 邻居列表构建摊薄（$\div 48$） | 10–20%（构建本身占单副本 ~15–25%） |
| 参数读取（**评审 Minor 也纠了我的措辞**：广播的只是基准参数，λ 相关参数是合并读取） | 3–7% |
| launch 摊薄 | **1.5–3%**（原写 10–30%） |
| occupancy | **≈ 0**（直空间已饱和） |
| **合计** | **移除 15–30% 单步时间 ⇒ 加速 1.2–1.4×** |

## 但这不推翻批量设计 —— 它推翻的是批量设计的**理由**

这是我认为最重要的自我修正。我原来给批量副本的辩护是"吞吐加速 5–10×"，这个辩护现在垮了。但批量副本的真正价值在别处，而且更硬：

1. **$u_{kn}$ 与 HREX 要求副本共驻**。48 副本同卡是"每 50–100 步做全对 Gibbs 交换 + 顺路拿全 $u_{kn}$"的**必要条件**，不是优化。这个能力的价值在采样效率上（往返率、混合时间），不在 ns/day 上。
2. **共享邻居列表省显存**，让 48 副本装进 80 GB。
3. **调度单元干净**（一卡一配体对）。

**顶层指标本来就是"每 GPU-day 产出的收敛 $\Delta G$"**，而混合效率的改善直接乘在这个指标上。如果 HREX 让每个 λ 的有效样本数翻倍，那等价于 2× 吞吐，且它来自采样而非算力 —— 这才是批量设计真正买到的东西。

## 修改

- **§10 M2 验收线从"≥5×"改为"≥1.2× 且与 E0 预测区间相符"**，并把 red flag 从"<4×"改为"**偏离 E0 预测区间下界超过 20%**"
- **新增靶子（这才是主指标）**：HREX 往返率 ≥ X / ns、每 λ 的 $\tau_{\text{int}}$ 相比无交换降低 ≥ Y 倍，X/Y 由 M3 的谐振子 + 小体系实测定标
- **§7 CUDA Graph 的动机改写**：从"性能"改为"确定性与代码简洁"，性能收益标注 1.5–3%
- **§14 溯源表**新增行：单步时间、launch 占比、批量加速上限，全部指向本节 roofline

评审说"E0b 之前先交逐部件 roofline" —— 我认为顺序应该反过来一半：**roofline 已经足以否掉 5× 这个数**，E0b 现在的作用变成验证 roofline（特别是 PME 铺展/FFT 占比，那部分我还没算），而不是发现头寸。

### 预平衡改为 R=1 串行，引擎**永不**存在多副本 barostat

```
阶段 1  最小化                    R=1, λ=0
阶段 2  NVT 升温 50 ps            R=1, λ=0
```

## A.3 — 接受，这是 §14 的第一次实战检验，而我第一次就没通过

评审说得对：**skin 总量不变时列表大小不变，变的是重建频率。** 我写"list 大 30%"是把两个东西搞混了。正确的账：

- $d_{\text{thresh}}: 0.125 \to 0.05$ nm ⇒ 扩散主导下重建间隔 $\propto d_{\text{thresh}}^2$ ⇒ **频率涨约 6×**
- 列表大小**不变**（skin 仍 0.25 nm）
- 若为了压回重建频率而加大 skin 到 0.35 nm，则列表大小按 $(1.35/1.25)^3 \approx 1.26$ ⇒ 大 26%，且直空间对数也涨 26%（在计算受限的情况下这直接是 26% 性能损失，比我原以为的贵）

**这个纠正与第一部分的 roofline 联动**：既然直空间是计算受限且占主导，**skin 的每一点增加都是直接的性能税**。所以 C1 的正确处置应该偏向"低阈值 + 高重建频率"而不是"加大 skin"，因为列表构建成本被 48 副本摊薄了（$\div 48$），而对数成本没有。这是个我之前没做对的权衡方向。

**修正后的 skin 预算**（含评审要求的显式 margin 项）：

$$\text{skin} = 2 d_{\text{thresh}} + s_{\text{window}}(K) + m_{\text{margin}}$$

$d_{\text{thresh}} = 0.05$、$s_{\text{window}} = 0.12$、$m_{\text{margin}} = 0.06$ ⇒ skin $= 0.28$ nm。三项之和不再恰好为零。

**三处小错全部接受**：
- checkpoint 是 $x + v$ = 138 MB（不是 276）
- 回滚 checkpoint **不存 $F$**（回滚稀有，重算力即可）—— 与 m8 一致
- **$s_{\text{window}}$ 声明为性能参数，非正确性参数**。这一条我要强调它的方法论价值：评审指出"实测 max + 50%"在极值统计上系统性低估尾部，这是对的（尾部指数衰减，样本 max 是有偏估计）。**正确性由 flag 回滚机制单独兜底，$s_{\text{window}}$ 只决定回滚多不多。** 这样 $s_{\text{window}}$ 就可以自由调优而不需要正确性论证 —— 这是个比"把它算准"好得多的结构。

# 第三部分：B1 — 接受，这确实是地基，而且我原设计会当场红

评审 B1 是这一轮技术含量最高的一条。我确认它是对的：

我为直空间的力累加设计了 Q24.40 定点，理由是"整数加法可交换 ⇒ 与线程调度无关"。但**电荷铺展入 PME 网格是同一个模式的 atomic 累加，而我完全没管它**。若用 fp64 `atomicAdd` 铺展，则：

$$\rho(\mathbf{r}) \text{ 的末位随线程调度漂移} \;\Rightarrow\; \text{FFT 输入漂移} \;\Rightarrow\; \text{M15 当场红}$$

而 M15 恰恰是我在 C2 里立起来、用来支撑"固定 plan 下确定性仍然成立"的那条断言。**所以我的 C2 方案有一个我自己没检查的前提。**

## 处置：铺展走定点网格，与 Q24.40 同族

```
grid_accum : int64[128³ × R]     Q格式，定标位数独立于力（电荷量纲不同）
spread  : q_i × B-spline 权重 → 定点 → atomicAdd(int64)
convert : int64 grid → fp64 grid（确定性逐点转换）→ cuFFT
```

**显存**：$128^3 \times 48 \times 8\text{B} = 805$ MB。可接受（原 fp64 实空间网格本来也要 805 MB，是**等价替换而非新增**）。

**定标选择**：电荷网格的动态范围比力小得多（单位电荷铺展到 $4^3$ 个网格点，网格电荷密度 $|\rho| \lesssim 10$ e/nm³ 量级）。可以用比 Q24.40 更激进的小数位数，比如 **Q16.48**，分辨率 $3.6\times10^{-15}$。具体位数走与力累加器相同的流程：**编译期常量 + 溢出断言 + 在断言保护下搜索**。

**为什么这比"固定序分段归约"好**：固定序归约要么牺牲并行度，要么需要按网格点组织的两阶段 scatter（额外显存 + 额外 kernel）。定点方案是零成本的同构扩展，且**复用已有的溢出检测基础设施**。

## 连带影响（这才是 B1 真正值钱的地方）

一旦把"定点累加"确立为**所有 atomic 归约的无条件政策**，就应该系统性地扫一遍还有哪些地方在做浮点 atomic：

| 位置 | 现状 | 处置 |
|---|---|---|
| 直空间力 | Q24.40 ✓ | — |
| PME 铺展 | **fp64 atomic ✗** | → 定点（本条） |
| PME 力回插（gather） | 需检查 | 是 gather 不是 scatter，无 atomic，安全 |
| 能量归约 | 固定形状树形 | 保留，但需断言树形形状是编译期常量 |
| $\partial U/\partial\lambda$ 累加 | 定点 ✓ | — |
| 约束（CCMA）的残差归约 | **未设计 ✗** | → 见 B6 |
| 虚位点力分配 | N/A（已拒绝虚位点，m6） | — |

**新增 §3.3「归约政策」**：*引擎内任何跨线程的浮点累加都必须走定点，或必须有编译期固定的归约形状。新增任何 `atomicAdd(float/double)` 视为规格违反。* 这条写成 CI 可检的静态规则（grep + 白名单）。

评审说这"必须在 M0 前拍板"——同意，且我认为它应该和 §3.1 合并成一节，因为它们是同一个原理的两个应用，而我之前只写了一个应用就以为覆盖了原理。**这是"条件性成立写成无条件成立"的又一个实例：我写的是"定点累加保证确定性"，实际成立的是"定点累加的那些量的确定性"。**

# 第四部分：B 节 Major 逐条

## B4 — 接受，这是硬错误，我必须承认

$\S 4.3$ 我写的是 $\alpha(1-\lambda)^2$，A2 钉的是 openmmtools `a=1, b=1, c=6`。Beutler 软核的一般形式：

$$U^{sc} = 4\lambda^a \epsilon\left[\frac{1}{\left(\alpha(1-\lambda)^b + (r/\sigma)^c\right)^2} - \frac{1}{\alpha(1-\lambda)^b + (r/\sigma)^c}\right]$$

我写 $b=2$，A2 钉 $b=1$。**spec 内部矛盾，第一天跑 A2 就会撞。**

而这条错误的成因值得记录：$b=2$ 是我从记忆里取的（$(1-\lambda)^2$ 在某些实现里确实用，因为它让 $\partial U/\partial\lambda$ 在 $\lambda \to 1$ 处更平滑），而 $b=1$ 是 openmmtools 的默认。**我把两个不同实现的参数混装在一份 spec 里，这正是 M-b 说的"把语义外包给第三方"的后果** —— 如果我一开始就写完整解析定义并自己选定参数，就不会出现这种混装。

**处置**：§4.6 必须**先**冻结 $(a, b, c, \alpha)$，且给出选择理由（$\partial U/\partial\lambda$ 在端点的行为、$\lambda$ 调度的匹配），然后 A2 的 openmmtools 配置**按这个选择去配**（openmmtools 的软核指数是可配的）。**方向是 spec → A2，不是 A2 → spec。**

## B5 — 接受，且这条比评审说的更狠

评审指出：RNG 种子含 atom 数组下标 ⇒ 原子重排后同一物理原子分到不同随机流 ⇒ **轨迹级分叉，力累加器根本轮不到出场**。

我确认这个逻辑，而且要补一句：**M6（原子重排序不变性）在原设计下不是"会红"，而是"必然红且无法修"** —— 因为随机力本身就不同了，这不是舍入误差。我把"定点累加保证原子序无关"这个**单点能量**层面的正确结论，错误地外推到了**轨迹**层面。

**处置**：
- 种子改用**稳定 atom ID**（ingest 时按拓扑序分配，与内存布局解耦），种子 = `(global_seed, step, stable_atom_id, state_id, dof)`
- **M6 降级为只断言单点能量/力位级**，明确不断言轨迹
- 新增 **M6b**：原子重排后，**同一 stable_atom_id 的随机力序列位级相同**（这才是可测且有意义的）

注意我把 `replica` 改成了 `state_id` —— 这是 B7 的伏笔。

## B6 — 接受，需要设计决策

CCMA 是迭代求解，收敛判据式迭代的归约顺序若随 tile/block 形状变，M3 破。而且这个问题和 B1 同源（跨线程归约）。

**处置**：**固定迭代次数**（不用残差判据），迭代次数在 ingest 时按体系确定并写入 manifest，配一条断言"该迭代数下残差 < 阈值"。这样：
- 归约形状编译期固定 ⇒ M3 保住
- 残差判据从"运行时分支"变成"离线验证 + 运行时监控"
- graph 友好（无数据依赖分支）

代价：迭代数要取保守值（比自适应多几轮）。约束求解占单步时间几个百分点，可接受。

**并入 §3.3 归约政策**：CCMA 的残差归约也走定点或固定形状。

## B7 — 完全接受，这是我"零成本 HREX"叙事的最大漏洞

评审列的清单我照单全收，而且它揭示了一个概念错误：**我一直在说"交换 λ"，但实际需要交换的是"整个热力学态的全部附属状态"。**

正确的抽象是引入**槽位（slot）/ 态（state）二元区分**：

| 概念 | 定义 | 交换时行为 |
|---|---|---|
| **slot** $r$ | 显存中的一列（$\texttt{x}[\cdot][r]$），构象所在 | **不动** |
| **state** $s$ | 一组热力学参数：$\boldsymbol\lambda$、REST2 $\beta$、ALF 偏置系数 | **在 slot 间置换** |

必须显式定义归属的量：

| 量 | 归属 | 理由 |
|---|---|---|
| 坐标 $x$、速度 $v$ | **slot** | 构象不动 |
| $\boldsymbol\lambda$、$\beta$ | **state** | 定义 Hamiltonian |
| ALF 偏置系数 | **state** | 是 $\lambda$ 空间的偏置 |
| MSλD 的 $\theta$ | **slot**（若与 HREX 共存则见下） | 是构型自由度 |
| $\theta$ 的动量 | **slot** | 同上 |
| $\partial U/\partial\lambda$ 累加器 | **state** | 后处理按态聚合 |
| $u_{kn}$ 的行标签 | **state**（列标签是采样时刻） | MBAR 输入语义 |
| RNG 的第 4 维 | **slot** | 与坐标绑定，否则 O 步的随机力语义错乱 |
| permutation 日志 | 全局 | 后处理必需 |

**RNG 那一行是关键**：我原设计写 `replica` 是含混的。它必须是 **slot**，因为 Langevin 的 O 步作用在坐标上。如果它绑到 state，交换后同一构象的随机力流会跳变，破坏细致平衡。**这个 bug 会表现为"HREX 开启后温度略微不对"，极难归因。**

**MSλD × HREX 的关系**：评审指出未定义。我的决定是 **M3 阶段两者互斥**（配置层强制），理由：
- MSλD 的 $\theta$ 是连续 λ 动力学，HREX 是离散 λ 置换，嵌套需要**专门的移动类型 + 独立的细致平衡推导**
- 二者解决的是同一个问题（λ 空间混合），叠加的边际收益不明
- 嵌套版本进 backlog，且必须附推导

**雷区 #12 的注入测试**扩展到评审列的四类：$\theta$ / ALF 系数 / $u_{kn}$ 态标签 / REST2 $\beta$。

## B8 — 接受，而且这条让我改了 HREX 的拓扑

评审说对了一件我完全没想到的事：**Gibbs 全对交换把两个 repeat 耦合成单一马尔可夫网络后，"2 个独立重复"这个词就没有意义了。** 而我整个收敛诊断和调度器的杀任务逻辑都建在"两条独立链的一致性"上。

这是个真正的两难：全对交换混合更快，但独立重复给我一个**免费的、不依赖模型假设的**收敛诊断。

**我选评审的第一个选项：2 × 24 两个独立交换网络。**

理由：
- **独立重复的诊断价值极高且不可替代**。两条链的 $\Delta G$ 差异是唯一不依赖"$\tau_{\text{int}}$ 估计对不对"的收敛证据，而 $\tau_{\text{int}}$ 估计本身在 HREX 下是出名地不可靠（态在 λ 空间游走，时间序列非平稳）
- 24 副本内的全对 Gibbs 已经比相邻交换强很多，退到 24 的混合损失远小于失去独立诊断的损失
- 调度器的"方差不够就续跑 / 不值得就杀"逻辑保持有效
- 两个 24 网络的交换是两个独立的 $24\times24$ 判据，实现上更简单

**代价**：$u_{kn}$ 变成两个 $24\times24$ 块而非一个 $48\times48$。MBAR 可以分别解再合并（两个独立估计 + 加权），也可以合并解（把两个网络的样本都当作来自 24 个态的样本 —— 这是合法的，MBAR 不要求样本来自单一链）。**后者更优**：合并解得到更小的方差，同时两条链**分别**解出来的结果仍可用作收敛诊断。两者不冲突。

**新增靶子**：往返率、λ 占有率均匀性 —— 这些替代原来靠"独立重复"隐含承担的一部分诊断职责。

## B9 — 接受，一行修改防一个细致平衡破口

**强制"交换步 ≡ 能量计算步"**，写进 §8：

```
每 50–100 步(交换步):
    算交换所需能量(当前 slot 构象在候选 state 下的 U) ← 必须是当前构象
    执行 Gibbs 全对(24)
每 M 步(M ≫ 交换间隔):
    算全 u_kn 矩阵 → 落库(MBAR 用)
```

关键点：**交换判据用的能量必须是当前时刻的，不能复用上次全矩阵的陈旧值**。而交换只需要 $24\times24$ 中实际被 propose 的那些元素，用二次型展开（C3）后成本很低。全矩阵可以降频（MBAR 只需要足够的去相关样本，不需要每次交换都存）。

这条修改把"交换成本"和"MBAR 数据成本"解耦了，其实还省了钱。

## B10 — 接受，且 release 关溢出检查这条我认输

评审的措辞很准：**"可复现的静默反号力"**。在一个位级确定的系统里，溢出会**可复现地**传播，而所有等价性断言（M1/M3/M4/M6）**照常全部通过** —— 因为两边都同样地错了。这是我 §3.1 里"release 关闭但代码必须存在"的直接反驳，我接受。

**修正后的溢出政策**：

| 累加 | **饱和而非回绕** + **粘滞标志位**（sticky flag，一旦置位不清除） |

## B11 — 接受，纯相对容差是个初级错误

湮灭端点、软核关闭区、力近零处，$\text{rel} = |a-b|/|b|$ 的分母趋零。改为双门：

$$|a - b| < \epsilon_{\text{abs}} \;\lor\; \frac{|a-b|}{\max(|a|,|b|)} < \epsilon_{\text{rel}}$$

$\epsilon_{\text{abs}}$ 按量纲给：力 $10^{-8}$ kJ/mol/nm，能量 $10^{-8}$ kJ/mol。**A1/A2/M 系列全部适用。**

## B12 — 接受，A7 只覆盖了接受率一项

评审对："注入测试只测 plumbing 不测 sampling"。补齐系综级 HREX 验证：

| ID | 断言 |
|---|---|
| **A7a** | 双态谐振子的解析接受率（原 A7） |
| **A7b** | **交换开/关下，每个 λ 的边缘分布一致**（KS 检验）—— 这是 HREX 正确性的定义性质 |
| **A7c** | 接受率 vs 相邻态的理论重叠（$\Pi$ 或 Bhattacharyya 系数） |
| **A7d** | 往返时间分布、λ 占有率 vs MBAR 预测的权重 |

A7b 是最重要的一条：**HREX 不改变每个态的平衡分布**，这是它的全部正确性内容。如果这条成立，接受率再低也只是效率问题；如果这条不成立，结果就是错的。

## B13 — 接受，E0a 是代理而非答案

评审对：OpenMM `mixed` vs `double` 只给下界，因为 OpenMM 的 mixed 模式和我要做的"f32 计算 + 定点累加"不是一回事，而且它的两条路径优化程度不同。

**E0 补 E0d**：同体系、同邻居列表、内核级 f32 vs f64 微基准，分项（direct / spread / FFT / 约束 / 积分）。这个才是决策依据。

我仍然倾向先做 fp64 单路径（正确性优先，且 SPFP 有 DPFP 作天然 oracle，后加不难），但我要把这个权衡明确写进开放项 1，并把它的量级从"1.3–1.8× 损失"更新为"可能接近 2×，且它是最大的单项性能杠杆"。

# 我对 E 节总体判断的回应

评审说"这三件事不拍板，M0 的『慢的 $O(N^2)$ fp64 直算定义语义』会定义出一套上了 GPU 就兑现不了的语义"。

**这句话我认为是这两轮评审里最重要的一句**，因为它指出了我 M0 策略的一
…我 M0 策略的一个根本缺陷：**我把"定义语义"和"定义可实现的语义"当成了同一件事。**

M0 的原计划是"慢的 $O(N^2)$ fp64 直算版本即可定义语义"。这个策略隐含一个假设：语义与实现无关，先定语义再谈性能。但 B1–B3 揭示的三件事**全都是语义与实现的耦合点**：

| 地基决定 | 在 $O(N^2)$ 直算版本里的样子 | 上 GPU 后的样子 |
|---|---|---|
| 铺展确定性 | $O(N^2)$ 版本没有网格铺展，或用单线程循环 —— **确定性免费成立** | atomic scatter，确定性需要定点网格才成立 |
| barostat 系综 | $R=1$ 直算，教科书 NPT —— **语义无歧义** | 多副本共享盒的联合系综，语义需要专门推导 |
| 性能账 | 与语义无关，不出现 | 决定 skin、$K$、精度、批量规模 —— 而这些**回头改语义** |

所以"慢而正确的语义定义"这句信条，只在**语义确实与实现解耦**时才有效。而它对第三列的三行都不成立。这是我信条 1 的适用条件，我从来没写出来。

## 修正后的 M0 策略

M0 的产物不再是"一个慢的参考实现"，而是**两个东西的配对**：

```
M0 交付 = 语义定义(慢参考实现)  +  可实现性证明(该语义在目标架构上的构造性论证)
```

**"可实现性证明"具体是什么**：对每一条 M0 立下的位级/容差断言，附一份说明"在目标 GPU 实现中，这条断言由哪个机制保证"。比如：

| M0 断言 | 慢参考实现里靠什么成立 | GPU 实现里靠什么成立 | 是否同源 |
|---|---|---|---|
| M1a 直空间位级 | 单线程串行 | Q24.40 定点 atomic | ✓ 不同机制，但都成立 |
| M15 run-to-run 位级 | 无并发 | **定点网格铺展**（B1 新增） | ✓（补上后） |
| M3 与 tile 形状无关 | 无 tile | 定点 + CCMA 固定迭代数 | ✓（补上后） |
| M5a 格矢整数平移位级 | 精确 | PME 网格周期性 | ✓ |
| ~~M5 任意平移位级~~ | 精确（$O(N^2)$ 无网格！） | **不可能** | ✗ 已降级 |

**最后那一行正是这个新流程要抓的东西**：$O(N^2)$ 直算版本在 M5 上会给出比 GPU 实现**更强**的性质（无 PME 网格 ⇒ 任意平移精确不变），如果我用它定义语义，就会定出一条 GPU 永远无法满足的断言。而这就是评审说的"定义出一套上了 GPU 就兑现不了的语义"的具体机制。

**规则**：M0 的参考实现**必须包含 PME 网格**（不能用 $O(N^2)$ 直接 Ewald 求和绕过），否则它定义的对称性性质强于真实实现。慢可以，但**结构必须同构**。这是对原 M0 计划的实质修改。

同理：
- 参考实现必须**包含定点累加**（否则定义出的确定性性质是"因为串行"，不可移植）
- 参考实现**不得**包含解析维里（否则定义出压强语义，而生产不实现）
- 参考实现的 barostat 必须是 $R=1$（与新的预平衡协议同构）

**成本**：M0 变重了，从"两周写个直算版"变成"写一个结构同构但慢的完整实现"。但这个成本是**必须付的**，因为替代方案是在 M1/M2 发现语义定错然后回改 —— 而那时已经有一堆测试建在错的语义上。

# 三个我还欠着的决定

## 1. B4 的软核指数：我选 $a=1, b=1, c=6$

既然方向是 spec → A2，我需要给出选择理由而不是跟随默认。

考察 $\partial U/\partial\lambda$ 在 $\lambda \to 1$（完全耦合端）的行为。软核项 $\alpha(1-\lambda)^b$ 在此处趋零，即软核退化为标准 LJ。取 $b=1$ 时：

$$\frac{\partial}{\partial\lambda}\left[\alpha(1-\lambda)\right] = -\alpha \quad (\text{有限、非零})$$

取 $b=2$ 时导数趋零，$\partial U/\partial\lambda$ 更平滑 —— 这是我记忆里 $b=2$ 的动机。

**但这个"更平滑"是骗人的**：$b=2$ 让软核参数在端点附近变化过慢，意味着 $\lambda$ 窗口在端点附近**浪费**（相邻窗口的 $u$ 分布几乎重叠，$\partial U/\partial\lambda$ 变化都挤在中段）。$b=1$ 配合非均匀 $\lambda$ 调度（端点加密）是更标准也更可控的组合。

而且更实际的理由：**$b=1$ 让 $u(\lambda)$ 对 $\lambda$ 的依赖阶数更低**，与 C3 的二次型展开在结构上更兼容 —— $b=2$ 会在软核分母里引入 $\lambda^4$ 项，虽然 LJ 侧本来就不做倒空间展开，但保持整个 IR 的表达式阶数一致对常量折叠和 lower 有实际好处。

**冻结**：$\alpha = 0.5$、$a = 1$、$b = 1$、$c = 6$。$\sigma/\epsilon$ **先组合后软核**（Lorentz-Berthelot 组合规则作用于 λ 插值后的 per-atom 参数，然后代入软核公式）—— 这个次序也要写死，因为它与"先软核后组合"给出不同能量。

# 一句总结我这轮学到的

两轮评审揭示的不是 12 个 + 13 个独立缺陷，而是**同一个认知习惯的 25 次显形**：我倾向于把"在我脑子里那个场景下成立"的结论写成无条件命题，而丢掉产生它的那个场景。

$\S 14$ 溯源表治的是数字的这个毛病。但 B1/B5/B6/B7/B10 说明**断言**也有同样的毛病，而它们更危险 —— 一个错的数字会让性能不达标（可见），一个漏了条件的断言会让 gate 通过而结果是错的（不可见）。

所以 §14 要扩成两张表：**量化断言溯源表** + **不变量适用域表**，后者对每条 M/A 断言写明"在什么条件下成立、哪个机制保证、哪些变更会使其失效"。上面那张"可实现性证明"表就是它的原型。
