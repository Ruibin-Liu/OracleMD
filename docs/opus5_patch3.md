# P1 — 接受矛盾的存在，但两个数都不该写进 spec

## 先承认矛盾

## 但我要指出 P1 结论的同一个病

$$\text{红利} = \frac{\eta_{\text{batch}}}{\eta_{\text{serial}}} \times f_{\text{amortize}}$$

这个**公式**我完全接受，它是正确的分解。但代入的两个数：

## 数值处置

$K=50$ @ 4 fs = 200 fs 窗口。漂移标度：

- 弹道（短时，$t < \tau_{\text{coll}}$）：$\propto t$ ⇒ **×2**
- 扩散（长时）：$\propto \sqrt t$ ⇒ **×1.41**

200 fs 在水中处于两者之间，取保守的弹道 ⇒ $s_{\text{window}}$ 从 0.12 需增到 ~0.24 nm，skin 从 0.28 → 0.40 nm。而 A.3 已经确认：**skin 增加是直接的性能税**（列表大小 $\propto$ skin 半径立方，且直空间计算受限）：

$$(1.40/1.28)^3 \approx 1.31 \quad\Rightarrow\quad \text{对数与直空间时间 +31\%}$$

**不接受。选另一支：$K$ 减半到 25。**

理由是 P4 的副产品：**graph 的 launch 收益只有 1.5–3%，所以 $K$ 是个几乎免费的旋钮。** $K: 50\to25$ 使 launch 占比翻倍（3–6%），换来 skin 维持 0.28 nm、避免 31% 的对数税。这个交换比是 ~1:10，毫无悬念。

**并且这条推理只有在 P1/P3 的 roofline 存在之后才做得出来** —— 没有它我会本能地保 $K$（因为我原以为 graph 值 10–30%）。这是 roofline 的第一次实际决策价值，值得记一笔。

# P3 — 接受，并按它的估算更新，全部标 provisional

48 路 $128^3$ fp64 FFT（正+逆）+ 铺展/回插：

$$\underbrace{2.1\times10^{10}}_{\text{FFT}} + \underbrace{7\times10^{9}}_{\text{spread/gather}} \approx 2.8\times10^{10} \;\text{FLOP/步} \quad (\approx +40\%\ \text{于直空间的} 7.1\times10^{10})$$

且 FFT 的 achieved-% 低于直空间（带宽受限 + 全局转置）。修正：

| 量 | 原（provisional） | 修正（provisional） |
|---|---|---|
| 单步时间 | 15–18 ms | **20–26 ms** |
| 每副本 @ 4 fs | — | **13–17 ns/day** |
| 总吞吐 | 460–550 ns/day | **620–820 ns/day** |
| 理论上限/副本 @ 2 fs | 17 | **~12**（含 PME FLOP） |

**§10 原靶子（30–70 @ 2 fs）超出理论上限 2.5–6 倍。** 死得比上一轮更透。

**接受"E0b 必须分开测 FFT 与直空间的效率"** —— 而且这正是 P1 的预测区间所需的输入：$\eta_{\text{batch}}$ 和 $\eta_{\text{serial}}$ 都是加权平均，而两个部件的批量红利故事完全不同：

- **直空间**：批量增加并行度，红利来自 occupancy 恢复
- **FFT**：批量 FFT 的红利来自**摊薄 kernel 启动与提高转置效率**，但 $128^3\times48$ 的工作集（805 MB）远超 L2，可能纯带宽受限 ⇒ **红利可能显著小于直空间**

所以 E0b 要出的是**分部件的 $\eta$ 矩阵**（部件 × {串行, 批量}），加权后才是 P1 的公式输入。§14 行 4b/4c 相应细化为分部件。

# 元观察 — 我接受，并提一个具体的流程实现

评审最后一段是三轮里最重要的一段：

> **人（包括写表的人自己）不会自觉执行这张表，只有流程会。**

P1（没穿透）、P2（没回查）、CCMA 迭代数（没登记）—— 三种失效模式，同一份表，同一个作者，同一天。这不是我不够仔细，是**自查在结构上不可靠**：我在写第五部分时的心智状态里，第 A.3 节已经是"完成的事"。

## 具体流程（建议写进仓库的 CONTRIBUTING，不只是 spec）

**1. 编号化**。§14 每行给稳定 ID（`Q-001` 量化断言 / `I-001` 不变量），spec 正文引用数字时必须带 ID：

```
skin = 0.28 nm  [Q-005]
```

**2. patch header 强制声明**。每份 patch 顶部必须有：

```
## 触发行声明
新增: Q-016 (CCMA 迭代数), Q-017 (NVE 漂移阈值 @4fs)
修改: Q-011 (步长 2→4 fs), Q-003 (launch 占比), Q-006 (重建频率)
回查通过未受影响: Q-001, Q-002, Q-004, Q-005(靠 K 减半吸收), Q-007..Q-015
```

**未列全 = patch 不予合入。** 这把"回查"从美德变成了准入条件。

**3. 机器可检的一半**。CI 检查：patch diff 里出现的每一个 `[Q-xxx]` 引用变更，是否都在触发行声明里。这抓不到"该改而没改"（P2 型），但能抓到"改了而没声明"。

**4. 抓 P2 型的唯一办法是反向索引**。§14 每行的"失效触发条件"列要**结构化**成关键词（`步长`、`K`、`R`、`精度`、`盒尺寸`、`cutoff`、`软核参数`…）。CI 从 patch 的触发行声明里提取被改的量，反查所有以该量为触发条件的行，**要求 patch 显式声明这些行的处置**。

P2 在这个机制下会被自动抓到：patch 声明"修改 Q-011（步长）" ⇒ CI 反查"失效触发含『步长』" ⇒ 命中 Q-005（skin）、Q-006（重建频率）、Q-003（launch）⇒ 要求声明 ⇒ 我必须处理。

**5. §14 提到正文**，并加一句我认为是这三轮最重要的自我约束：

> **本节的存在假设是：作者不会自觉执行本节。因此本节的每一条都必须有对应的流程或 CI 强制。无强制机制的表行等同于不存在。**

这句话是从"$s_{\text{window}}$ 是性能参数、正确性由 flag 回滚兜底"那个结构学来的 —— **不要指望把参数算准，要设计一个算不准也不出错的结构。** 表的问题同理：不要指望记得回查，要让不回查通不过。

---

一个给评审的问题，也是我现在唯一不确定该怎么排的事：**E0b 的分部件效率测量，需要一个已经能跑的批量实现才能测 $\eta_{\text{batch}}$ —— 而 $\eta_{\text{batch}}$ 又是 M2 验收线的输入。** 这里有循环：M2 要验收的东西，它的验收标准需要 M2 的产物来定。

我看到的出路是用**孤立微基准**打破循环：不实现完整批量引擎，只写"48 路批量的直空间对循环"和"48 路批量 cuFFT"两个独立 kernel，测它们的 achieved %。这能给出 $\eta_{\text{batch}}$ 的上界（无 kernel 间空隙、无同步、无列表构建），而 M2 验收线用"上界 × 已知折扣"。但这个折扣又是个拍的数。

**替代方案**：M2 不设绝对验收线，只设**回归线** —— 首次实现的实测值成为基线，此后任何 patch 不得使其下降超过 X%，同时要求实测值与 roofline 预测的**偏差有解释**（不是"必须落在区间内"，而是"落在区间外必须给出归因，归因写进 §14"）。这把 M2 从"验收门"改成"归因门"。

我倾向后者，但它弱化了 M2 作为 gate 的强度，想听你的判断。
