实测来了，这轮的价值和前三轮不同 —— 前三轮是逻辑复核，这轮是**两个地基假设各被实验判了一次，而且一正一反**。我先接受结论，然后指出这两个结果合在一起改变了我对"确定性从哪来"的理解。

# 一、E0e：C2 降级，但我不打算把它当好消息用

结果很干净：c2c/r2c/c2r、$64^3$ 到 $128^3$、含非 2 幂尺寸、batch 1→48，**全部位级相同**。合理，因为 batch 在 cuFFT 里就是跨 transform 的独立并行维，per-transform 的 twiddle 路径与归约树不该随它变。

**接受处置**：M1 位级整体保住，M1a/M1b 分层从常态降为保险条款，plan manifest 哈希照旧，E0e 改常驻 CI 回归。

但我要给这条加一句限定，因为我上一轮刚犯过"把实测当合同"的错：

> **M1b 的存在理由不是"我们观察到差异"，而是"我们没有合同保证不出现差异"。** 预期模式是 M1b 永不触发；若触发，正确反应是**调查 plan 参数变更**，而不是放宽容差。

这句话必须写进 spec，否则三个月后有人看到"M1b 从未触发"就会把它删掉，然后在某次 CUDA 升级后位级测试红成一片而无人知道该往哪查。**这是"不变量适用域表"的典型条目：一条永不触发的保险，它的价值全在于失效时告诉你去哪看。**

对应 §14 登记：

| ID | 内容 | 依赖 | 失效触发 |
|---|---|---|---|
| `I-012` | PME 倒空间位级可复现 | **实测**：cuFFT per-transform 数值与 batch 无关（driver 580.105.08 / CUDA 13.0 / cuFFT 12.x） | 换 driver / CUDA / cuFFT / 架构；改 plan 参数（batch、尺寸、layout、precision） |
| `Q-010` | M1b 容差 $10^{-12}$ | 保险条款，非实测值 | — （触发即调查，不放宽） |

`I-012` 的"依赖"列第一次写的是**实测环境的具体版本号**，而不是一个物理推理。这是这份 spec 里第一条经验性不变量，它的脆弱程度和其他条目不同，应该在表里显式标注类别。**建议不变量表加一列「类别」：`推导` / `构造` / `实测`。** 三类的复核频率完全不同 —— 推导类只在假设变时复核，构造类由 CI 保证，**实测类必须在每次工具链变更时重跑**。

# 二、M-B1：这条实测比 B1 的原始论证强，而且强在一个我没预料的方向

原始 B1 说的是"跨配置（block=128 vs 512）不一致"。实测给的是：

| 测试 | 结果 |
|---|---|
| block 128 vs 512 | DIFF，87342/2.1M，maxrel $1.6\times10^{-11}$ |
| **同配置 run-to-run ×5** | **全部 DIFF**，~$1.5\times10^4$/2.1M |
| int64 Q16.48 | 位级相同 |

**"同配置 run-to-run 也 DIFF"这一条把 fp64 atomic 铺展从"违反 M3（形状无关）"升级为"违反最基本的可复现性"。** 这不是我原本理解的那个问题。M3/M4/M6 都是"跨某个维度的等价"，可以通过分层容差安抚；而 run-to-run 不稳定意味着**同一个二进制、同一份输入、同一台机器，跑两次结果不同** —— 这直接摧毁调试能力本身，与任何断言无关。

我上一轮把定点铺展定位成"§3.3 归约政策的一个应用"，太轻了。**正确定位：它和 Q24.40 力累加器是同一根承重柱的两半，而我此前只画了一半。**

关于评审那句谨慎的注脚 —— "run-to-run DIFF 在有竞争下测得，空闲机上可能碰巧一致，但原子加顺序从来没有合同保证，竞争只是让无保证变得可见" —— 我认为这句话比测试结果本身更重要，理由是它揭示了一个**测试方法论的意外收益**：

> **在满载 GPU 上跑确定性测试比在空闲 GPU 上更灵敏。**

空闲机上 SM 调度接近确定，block 到 SM 的映射稳定，浮点 atomic 的顺序可能碰巧稳定 —— 于是测试通过，而 bug 在生产（多任务共享卡、不同占用状态）时随机现身。这正是最难归因的那类故障。

**所以我要把这条写进 §11 的测试执行规范**：

| 规则 |
|---|
| 所有 run-to-run / 形状无关类断言（M3, M6b, M15, I-012）**必须在 GPU 有并发负载的条件下执行**。CI 需提供一个 contention 注入器（另起一个占用 SM 的 spinner kernel），并在多个占用水平下重跑 |
| 空闲机上的通过**不构成通过** |

这条是从这轮实测里白捡的，我原来的测试计划完全没有这个维度。它也解释了为什么 E0e 的位级结果**可信度更高** —— 那是在竞争条件下测的，如果有 batch 相关差异，竞争会放大它而不是掩盖它。

## Q16.48 的两个后续决定

实测确认"定点和是精确参考"（与 fp64 的差异在 fp64 自身累加噪声量级，相消严重的网格点 maxrel $1.7\times10^{-8}$ 而绝对误差仅 $10^{-13}$ —— 这正是相对容差在近零处失效的实例，B11 双门的又一个证据）。补两笔：

**① Q16.48 的范围推导（欠 `Q-008` 的同族，这次一起补）**

$$|\rho_{\text{grid}}| \le \max_i |q_i| \times \max(\text{B-spline weight product}) \times N_{\text{overlap}}$$

4 阶样条下单原子最大权重积 $\le 1$，重叠原子数由网格间距 0.10–0.12 nm 与水密度定，$\lesssim 30$。取 $|q|_{\max} = 1.5$ e ⇒ 网格点电荷 $\lesssim 45$，整数部分 16 位（$\pm 32768$）余量三个数量级。**充裕，且与力累加器不同 —— 这里没有 clash 敏感性**（铺展是有界的，不像 $r^{-12}$）。所以铺展累加器**不需要 ingest max-force 门控保护**，只需要溢出粘滞标志兜底。这是个好消息：`Q-008` 的困难只在力累加器，不传染。

**② 定点网格是否作为 M0 参考实现的"精确 oracle"**

实测说"定点和是精确参考"。这意味着**定点铺展不仅更确定，还更准确**（消除了 fp64 累加的相消误差）。所以 M0 参考实现应当用定点铺展，而不是"参考实现用 fp64、生产用定点"—— 后者会让参考实现成为精度较低的一方，oracle 的方向就反了。这与我上轮定的"M0 结构同构"一致，但理由更硬了：不只是同构，**生产实现在这一项上严格优于朴素实现**。

# 三、接受 §14 行 6 的纠正，并且这次我要记录失败模式

评审说得对：重建率由物理漂移过程和 $d_{\text{thresh}}$ 决定，**按物理时间计与步长无关**。4 fs + $K$ 减半后窗口物理时长不变（100 fs），每 ns 重建次数不变，变的只是**每 step 的越界概率 ×2**（因为每步位移大一倍，但达到同一位移所需的物理时间不变）。

正确表述：

| # | 量 | 值 | 依赖 |
|---|---|---|---|
| `Q-006` | 列表重建间隔 | **~$X$ fs 物理时间**（由 $d_{\text{thresh}} = 0.05$ nm 与水的位移分布定，待 M0.5 实测定标） | $d_{\text{thresh}}$、温度、体系粘度 |
| `Q-006b` | 每 step 越界概率 | $\propto$ 步长（4 fs 下为 2 fs 的 2×） | 步长 |
| `Q-006c` | 每 ns 重建次数 | $= 10^6 / X$，**与步长无关** | 同 `Q-006` |

**失败模式记录（这是第四次同型，值得单独归类）**：

| 轮次 | 失败模式 | 具体 |
|---|---|---|
| 1 | 没穿透 | roofline 写下后没让它穿过同文档的其他数字（P1） |
| 2 | 没回查 | 改步长后没执行自己声明的失效触发（P2） |
| 3 | 没登记 | CCMA 迭代数是新参数但没进表 |
| **4** | **推理滑动** | 表行受影响 → 我回查了 → 但把"每 step 概率"和"每 ns 频率"混同，**结论碰巧对，推理是错的** |

第 4 类最危险，因为**前三类会被流程抓住，第 4 类不会**。触发行声明会强制我碰这一行，CI 反向索引会强制我声明处置 —— 但没有任何机制检查我的处置**理由**是否正确。而这次结论碰巧对（可接受），所以连事后也不会暴露。

我能想到的唯一防线：**§14 每行的"依赖机制"列必须写成量纲/标度形式，而不是自然语言。**

- ✗ "重建频率受步长影响"

# 四、M2 混合门：接受，且我认为它解决的问题比我问的更多

评审给的三层我全部接受：

```
① 硬地板   总吞吐 ≥ η_serial × (1 + 摊薄下界)，摊薄下界 1.10–1.15×
           ← 由 roofline 行 1(列表构建 ÷48)单项撑住,不依赖 occupancy 假设
           低于地板 = 实现 bug，无辩解空间
② 归因门   与 E0b 预测区间的偏离必须归因并写进 §14，不设斩杀线
③ 破环     η_serial 现在可测(E0a + M0 参考实现单副本内核)
           η_batch 上界用孤立微基准(批量 cuFFT ~半天；直空间对循环 RawKernel ~百行)
```

**"地板抓谎言，归因抓意外"** 这个提法我认为应该上升为整份 spec 的 gate 设计原则，因为它给了一个我此前没有的分类标准。回头看我立的所有 gate：

| gate | 类型 | 是否设对 |
|---|---|---|
| M1/M3/M4/M6/M15（位级） | **地板** | ✓ 二值、无辩解空间 |
| A1/A2（容差） | **地板** | ✓ 容差由 oracle 精度推导 |
| A7b（HREX 边缘分布 KS） | **地板** | ✓ 分布相同是定义性质 |
| A3（λ 路径无关性） | 地板 | ✓ |
| ~~M2（≥5× / ≥1.2×）~~ | **误设为地板，实为归因** | ✗ 已修 |
| m4（NVE 漂移阈值） | **？** | 需重新审 |
| 往返率 / $\tau_{\text{int}}$ 靶子 | **归因** | 需明确标注 |

**m4（NVE 漂移 $< 0.01\ k_BT$/ns/dof）这一条我现在怀疑也误设为地板。** 它的阈值来源是"fp64 + 2 fs + 约束下可达"，即经验值 —— 那它就是归因门（超了要解释，可能是 HMR 因子、可能是 CCMA 迭代数不足、可能是柔性微扰键），不是二值判定。但漂移的**符号性质**（单调上升 vs 随机游走）是地板：单调上升指示系统性能量注入，这是 bug 而非调优问题。

**处置：m4 拆分**

| ID | 类型 | 内容 |
|---|---|---|
| `M-m4a` | **地板** | NVE 能量漂移必须是随机游走型（长时间序列的线性回归斜率在置信区间内含零），**单调漂移直接失败** |
| `M-m4b` | **归因** | 漂移幅度 $< 0.01\ k_BT$/ns/dof，超出须归因 |

这个拆分是"地板抓谎言"直接推出来的：**符号是谎言检测器，幅度是调优指标。** 我此前把两者混在一个阈值里，结果是幅度超一点就红（过严）而符号错但幅度小就绿（过松）—— 恰好两头都错。

**§11 新增开头段落**：每条 gate 必须标注 `地板` 或 `归因`。地板必须二值且无辩解空间；归因必须指定偏离时的归因去处（写入 §14 哪一行）。**未标注的 gate 视为未定义。**

# 五、E0a/E0b/E0d 待窗口 —— 一个建议

脚本就绪、等 GPU 空闲，这个安排没问题。但 M-B1 的教训给了个反直觉的推论：

**时序测试要空闲机，位级/确定性测试要满载机。** 这两类测试的执行环境要求是**相反的**，而它们此前混在同一个"E0/M 系列"清单里。

所以测试矩阵应该按环境切分：

| 类别 | 环境要求 | 当前状态 |
|---|---|---|
| **时序类**（E0a/E0b/E0c/E0d、微基准、M2） | **独占 GPU**，util 门卫（已有，>20% 拒跑） | 待窗口 |
| **确定性类**（M1/M3/M4/M6/M15/I-012、M-B1 回归） | **contention 注入**，多占用水平 | 可现在跑，且**应该现在跑** |
| **数值/物理类**（A1–A8、M9、M16/M17） | 环境无关 | 可现在跑 |

**这意味着 GPU 被占满的这段时间不是纯损失** —— 它是确定性类测试的理想窗口，而那恰好是当前最需要地基验证的一类（B1 刚被实测改写，定点铺展的 Q16.48 位数选择、溢出粘滞标志、CCMA 固定迭代数的归约形状，全都可以在竞争环境下先验证）。

建议把 `contention 注入器 + 确定性测试套件` 提前到 E0a/E0b 之前跑，理由：不需要等窗口、且它验证的是 M0 前置项而非 M2 验收项。

关于测试自身那一课（r2c 漏写 `axes=(1,2,3)` 报出 maxrel=2.0 的假 DIFF）：我认为这值得进雷区库，编号 **#14 — 批量轴被误当变换轴**。理由是它在引擎里有一个精确同构的对应物：**$u_{kn}$ 矩阵、$\partial U/\partial\lambda$ 向量、slot/state 置换，全部是"物理轴 × 批量轴"的多维索引，而批量轴是本设计里最新引入、最不熟悉的一维。** 雷区 #12（索引错位）说的是标签错配，#14 说的是**轴的角色混淆** —— 后者更隐蔽，因为它不会报错，只会给出一个量纲上说得通的错答案。B7 的 slot/state 表是防它的，但表只覆盖了 HREX 一处；铺展、FFT、二次型展开系数 $A/B/C$、定点网格的 $[128^3 \times R]$ 布局，每一处都有同样的风险。

**处置：注入测试新增一类 —— 轴置换注入**。对每个含批量轴的张量操作，注入一次"批量轴与某物理轴互换"的错误，断言测试能抓住。评审自己的测试作者犯了这个错，这是最好的证据说明它值得一个专门的 gate。
