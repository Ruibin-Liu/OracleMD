# R1 — 接受，而且我要承认这是"归因错误"而非"覆盖不足"

我上一轮写的是：

> E0e 的位级结果**可信度更高** —— 那是在竞争条件下测的，如果有 batch 相关差异，竞争会放大它而不是掩盖它。

这句话的每个词都对不上。cuFFT 的 per-transform 数值路径与 SM 调度无关 —— FFT 内部的归约树是 plan 决定的静态结构，不是 atomic 竞争。**SM 竞争对 I-012 根本没有作用通道**，所以我说的"竞争会放大它"是无根据的。而真正的通道（workspace 可用量 → plan 选择 → 不同算法 → 不同数值）我完全没想到，直到本轮补测把它测了。

更糟的是：**我从 M-B1（真的对 SM 竞争敏感）的正确结论，泛化出了一条"所有确定性测试都要在竞争下跑"的规则，然后用这条规则去背书 I-012。** 这正是 E 节诊断的那个习惯的第六次显形 —— 从一个成立的具体案例外推出无条件命题，丢掉产生它的机制。而这次的特别之处是：**我外推的是一条测试规则，所以错误会伪装成严谨。**

## 处置：压力源矩阵，且必须由机制推导而非清单枚举

| 不变量类型 | 风险通道 | 压力源 | 状态 |
|---|---|---|---|
| atomic 顺序敏感 | 线程完成顺序 | **SM 调度竞争注入**（spinner kernel，多占用水平） | M-B1 已验证有效 |
| plan/算法选择敏感 | workspace 可用量 → 算法分支 | **显存压力注入 + plan 缓存清空** | 本轮补测覆盖 |
| 时钟/时序敏感 | 若存在 timing-dependent 逻辑 | 锁频/降频注入 | **应为空集**（见下） |
| 库版本敏感 | 内部实现变更 | 工具链变更时重跑（`实测`类规则） | 已有 |

**第三行我要主动收紧**：这份 spec 里不应存在任何 timing-dependent 逻辑。如果有，它本身就是缺陷。所以这一行的正确处置不是"配一个降频注入器"，而是**一条 CI 静态规则：引擎内不得读取时钟做控制流决策**（与 §3.3 禁止浮点 atomic 同类）。把一个压力源需求转化为一条构造禁令 —— 这与 R4 的方向一致。

**表格的元规则**（这是我认为比表格本身重要的部分）：

> **每条不变量在表中必须填写"风险通道"，且压力源必须由该通道推导。** 通道空白 ⇒ 该不变量的压力测试无意义，应删除而非保留（保留会产生虚假覆盖感）。

这条规则会立刻抓住我上一轮的错误：I-012 的通道我当时写不出来（因为我以为是 SM 竞争，但说不出竞争如何影响 FFT 归约树），而"写不出通道"本该是个警报。

# R4 — 接受，并且这条应该改写我对整个 §11 的定位

> 空闲机上的通过不构成通过，**但满载机上的通过也不构成证明**。压力测试是回归探测器，保证只能来自构造。

这句话点出我的测试计划有一个结构性混乱：我把**探测器**和**地基**放在了同一张表里，用同一种语言写，于是它们看起来同等可靠。

正确的分层：

```
地基(构造)   定点累加 · counter-based RNG · 固定归约形状 · 固定迭代数 · plan manifest 哈希
             ← 确定性由此成立。数学上成立,不依赖测试。
探测器(测试) 压力注入下的 run-to-run / 形状无关 / 重排不变
             ← 抓"地基被绕过了"(有人加了 float atomic、有人引入了运行时分支)
监护(实测类) I-012 型:我们没有合同,只有观察 + 工具链变更时重跑
             ← 抓"外部世界变了"
```

三层的**失效反应完全不同**，而这才是分层的实际价值：

| 层 | 失效时的正确反应 |
|---|---|
| 地基 | 数学/构造错误 —— 改设计 |
| 探测器 | 有代码绕过了地基 —— 找那段代码，不要放宽测试 |
| 监护 | 外部行为变了 —— 调查 plan 参数/库版本，**不要放宽容差** |

我上一轮已经为 M1b 单独写过"触发即调查，不放宽容差"这句话，但**没有意识到那是一整个类别的规则**，而是当成了一条特例。现在它归位了：**监护层的所有条目都遵守这条，M1b 只是第一个。**

**§11 开头改写**：现有的"每条 gate 标注 地板/归因"（第四轮加的）保留，但**再加一维**：`地基 / 探测器 / 监护`。两维正交：

| | 地板 | 归因 |
|---|---|---|
| **地基** | M1a, M3, M6b, A3, A7b | — （地基不该有归因门） |
| **探测器** | M-B1 回归, M15 压力变体 | — |
| **监护** | — | I-012, M1b（触发即调查，不是"偏离需归因"） |
| **（性能/物理）** | M2 硬地板, m4a | M2 归因段, m4b, 往返率靶子 |

空格本身有信息量：**"地基 × 归因"必须为空** —— 如果一条地基断言允许"偏离后给出归因"，它就不是地基。这给了我一个检查现有 gate 分类是否正确的形式判据。

# R2 — 接受，我 oversell 了，而且这次的错误类型值得单独记

我写的是"定点铺展不仅更确定，还更准确"，并据此论证 M0 参考实现该用定点。评审的算术对：

$$2^{-48} \approx 3.6\times10^{-15}\ \text{（绝对）} \quad\text{vs}\quad \text{fp64 对 } O(1) \text{ 项的相对舍入} \sim 10^{-16}$$

**单项量化误差定点差 ~30×。** 定点的赢面在求和不再累积误差，不在单项精度。

准确表述（写进 §3.3）：

> 定点网格是**量化后问题的精确解**：$\rho_{\text{fixed}} = \sum_i \text{quantize}(w_i q_i)$ 精确无误差，而 fp64 的 $\rho_{\text{fp64}}$ 在 $\rho_{\text{fixed}}$ 附近随机游走（游走幅度取决于加法顺序与相消程度）。**选择定点的理由是确定性与结构同构，不是精度优越。**

M0 参考实现用定点的决定不变，但理由更正为"与生产结构同构"（这本来就是第三轮定的 M0 原则，我不需要额外发明一个精度理由）。

**这次的错误类型是新的**，我把它记为第 5 类：

| # | 失败模式 | 本轮实例 |
|---|---|---|
| 1 | 没穿透 | roofline 未穿过同文档其他数字 |
| 2 | 没回查 | 改步长未执行自己声明的失效触发 |
| 3 | 没登记 | CCMA 迭代数未进表 |
| 4 | 推理滑动 | 每 step 概率 vs 每 ns 频率混同（结论碰巧对） |
| **5** | **超额辩护** | 一个决定已有充分理由（同构），我又给它加了一条更强但错误的理由（更准） |

第 5 类的危害机制：**它给决定加了一根假承重柱。** 将来若有人发现"定点单项精度其实更差"，可能连带推翻整个定点决定 —— 而真正的理由（确定性 + 同构）从来没被触及。**在一份靠不变量支撑的 spec 里，假理由比缺理由更危险，因为它会在别人复核时把真理由一起带走。**

**流程处置**：§14 的"依赖机制"列（第四轮已改为标度关系）新增约束 —— **每个决定只列必要理由，冗余的支持性论证移入注释并标注 `non-load-bearing`**。承重的和不承重的必须在排版上可区分。

# R3 — 接受，且这是我第一次看到确定性栈产生了"意料之外的红利"

评审指出：A7b（HREX 边缘分布 KS 检验）作为**地板门**不 flaky，前提是固定位级种子 ⇒ 结果确定。

这个观察对我有额外价值，因为它逆转了一个我一直隐含接受的权衡。我原本以为统计类断言天生只能是归因门（因为 KS 统计量有随机波动，阈值必然带主观性，容易 flaky）。但在**位级确定的栈上，KS 统计量是一个确定的数** —— 同种子同配置永远得到同一个 $D$ 值。于是：

- 基线 $D_0$ 可以固定，断言变成 $D = D_0$（位级）或 $D < D_{\text{threshold}}$（确定不 flaky）
- **统计断言可以是地板门**，这在非确定性栈上做不到

这是确定性投资的一项我没预料到的回报：**它把"统计测试"从归因门升级为地板门的资格**。而统计测试恰恰是覆盖最难覆盖那类错误的（B12 说的"只测 plumbing 不测 sampling"）。

**接受基线与 manifest 联动**：

| 规则 |
|---|
| 所有统计地板门（A7b, A8, m4a）的基线值与 `manifest_hash`（含种子、配置、软核参数、oracle 参照配置）绑定存储 |
| 种子或配置变更 ⇒ 基线自动失效 ⇒ 必须重定标并记录变更原因 |
| **禁止**在基线失效后沿用旧基线（CI 检查 hash 匹配，不匹配则测试 error 而非 fail —— error 表示"无法判定"，fail 表示"判定为错"，两者不该混） |

最后那个 error/fail 区分我认为重要：**"基线不适用"和"断言不成立"是两种不同的状态**，混同会导致换种子后一片红，然后有人为了让 CI 变绿去重定基线，而真实的回归就藏在里面。

**§14 新增登记**：

| ID | 类别 | 内容 | 风险通道 | 失效触发 |
|---|---|---|---|---|
| `I-020` | 构造 | 统计地板门在确定性栈上不 flaky | 若引入任何非确定性来源（float atomic、时钟依赖、非固定种子），全部统计地板门同时变 flaky | §3.3 违反；host RNG 未纳入 counter-based |

这一行的失效触发很有意思：**它是 §3.3 的下游依赖，而这个依赖此前不可见。** 如果有人为了性能在某处放宽了 §3.3，他会以为代价只是"位级测试要放宽"，实际代价包括"所有统计地板门降级为归因门"。这正是不变量适用域表该抓的东西。

一个问题，关于 R1 的表格我拿不定主意：**我上面把"时钟敏感"一行处置为一条静态禁令（不得读时钟做控制流），但 CUDA Graph 的 K 步窗口本身是否构成一种隐性时序依赖？** 窗口内不能分支，所以窗口长度 $K$ 是个**编译期常量**，这没问题。但 C1 的回滚机制是"窗口结束后 host 检查 flag，触发则该窗口作废重来" —— **作废重来意味着轨迹依赖于 flag，而 flag 依赖于窗口边界的位置**。如果 $K$ 是编译期常量，边界位置就是确定的，因此轨迹确定。但如果将来为了性能做"动态 $K$"（比如根据漂移自适应缩短窗口），**轨迹就会依赖运行时状态，位级可复现性立刻破裂**。

这算不算已经存在的隐性时序依赖，还是只是一个需要登记的失效触发条件（"引入动态 $K$ ⇒ 全部位级断言失效"）？我倾向后者，并把它作为 `I-021` 登记，但想确认这不是我又一次把地基问题当成登记问题处理。
