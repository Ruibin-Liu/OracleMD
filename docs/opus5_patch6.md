# S3 — 我问错了问题，正确答案让 masking 从容差档升到位级地基

我问的是"K 窗口算不算隐性时序依赖，还是只需登记 I-021"。这个二选一本身就错了，因为它假设"动态 K ⇒ 位级破裂"是既定事实，只在讨论怎么记录它。评审给的三段把这个假设拆了：

**(a) 当前设计不是时序依赖** —— flag 是坐标的确定性函数。确认，我的直觉对，但我没能说出为什么对，所以我不敢信它，才去问"要不要登记禁令"。**说不出机制的正确直觉在这份 spec 里等于没有。**

**(c) 才是真正的支点。** 轨迹对窗口边界不敏感的条件是 masking 位级严格：超 cutoff 的对贡献**严格为零**，不是"小到 $10^{-6}$"。因为：

$$\text{masking 严格} \;\Rightarrow\; F(\text{list}_A) = F(\text{list}_B) \ \text{对任意两个都是超集的列表}\;\Rightarrow\; \text{列表内容不进语义}\;\Rightarrow\; \text{重建时机不进语义}$$

反之若 masking 松动到 rel $10^{-6}$，则**列表内容是语义的一部分**，于是重建时机是语义的一部分，于是 $K$ 是语义参数。

## 这直接改了 M7 的档位

我此前把 M7（共享列表 masking）放在**容差档**（rel $< 10^{-6}$），理由是"masking 的误差远小于所有下游断言的容差"。这个理由现在看是第 5 类失败（超额辩护的反面：**用下游容差为上游松动辩护**）。它错在：

| 我以为 masking 支撑的 | masking 实际支撑的 |
|---|---|
| M1 的位级等价（批量 ≡ 串行） | M1 · **I-021（K 自由）** · **C1 回滚机制的语义中立性** · **checkpoint/restart 位级（m2）** |

第三项是我刚意识到的：**C1 的回滚"该窗口作废重来"要求重来后的轨迹与没触发回滚时位级相同。** 如果 masking 松动，回滚重来用的是新列表（重建过），原窗口用的是旧列表，两者力不同 ⇒ **回滚本身改变轨迹** ⇒ C1 的三层防护从"正确性保险"变成"轨迹扰动源"。这是个真实的破口，而它在六轮里从没被点出来过，因为它藏在 masking 的档位选择里。

第四项同理：checkpoint 恢复后重建列表，若 masking 松动则恢复后的轨迹与连续运行不同。

**处置：M7 从容差档移入位级档，且成为 §3 确定性专章的第五根柱子。**

```
§3 确定性的五根柱子(全部构造类,全部位级)
  1. 定点力累加        Q24.40
  2. 定点电荷网格      Q16.48                    ← 第四轮实测升级为前置
  3. counter-based RNG 按稳定 atom ID + 绝对步序
  4. 固定归约形状      含 CCMA 固定迭代数
  5. masking 位级严格  超 cutoff 贡献恒为 0      ← 本轮升级
```

第 5 根的实现要求（这是"位级严格"的具体含义，必须写死否则又是一句无条件命题）：

| 要求 | 理由 |
|---|---|
| masking 用**乘 0** 而非 `if` 跳过或 $\text{erfc}$ 自然衰减 | 乘 0 是位级恒等；$\text{erfc}(\alpha r_c)$ 在 cutoff 处约 $10^{-5}$，非零 |
| 判据用**同一个** $r^2$ 比较，与力计算共用寄存器值 | 若判据算一次 $r^2$、力算另一次（不同指令序），两者可能给出不同的边界归属 |
| 边界情形 $r^2 = r_c^2$ 的归属**编译期固定**（取 `<` 或 `<=`，选一个写死） | 浮点相等极稀有但非不可能，尤其在格矢整数平移测试（M5a）中会构造出精确边界 |
| 不得使用 switch 函数（若引入 LJ switch，其在 cutoff 处必须**解析为 0 且导数为 0**） | 与 M-c 的 LJ 侧决策联动 |

第三行是我原本会漏的：**M5a（格矢整数倍平移位级）会人为制造精确边界情形**，因为平移后某些对的距离会精确落在 cutoff 上。所以 M5a 和 M7 互为压力源 —— 这是 R1 压力源矩阵的一个新条目，且风险通道明确（浮点相等 → 边界归属分歧 → 列表内容差异 → 力差异）。

## I-021 按评审的形式登记

| ID | 类别 | 内容 | 成立条件 | 失效触发 | 探测器 |
|---|---|---|---|---|---|
| `I-021` | 构造/地板 | 轨迹与窗口边界位置无关 | masking 位级严格（M7 位级档）+ RNG 按绝对步播种 | masking 降级为容差档；$K$ 依赖非模拟状态（墙钟、kernel 完成时序、可用显存） | **M2 变体**：同一轨迹按 $K \in \{1, 5, 25, 50\}$ 切分重放，位级一致 |

那个 M2 变体探测器我认为价值超出 I-021 本身：**$K=1$ 与 $K=25$ 位级一致**这一条同时验证了 masking 严格、RNG 绝对步序、回滚语义中立、graph 与非 graph 路径等价 —— 四根柱子里三根加一个机制，用一个测试。而它几乎免费（同一份代码不同 $K$ 参数）。

**这条应该是 M2 的主测试而不是变体。** 我原来的 M2 是"graph_replay(K) ≡ K × step"，只比了 graph vs 非 graph；新形式"$\forall K$ 位级一致（含 $K=1$）"严格更强，且把非 graph 路径作为 $K=1$ 的特例包含进去了。

## 动态 K 的处置随之改变

既然 (a)(b)(c) 满足时动态 $K$ 不破坏可复现，那 backlog 里的"动态 $K$"从**禁区**变成**受条件许可**：

> **动态 $K$ 允许**，条件：自适应规则是模拟状态的确定性函数（例如"上窗口最大位移超过阈值 ⇒ 下窗口 $K$ 减半"，这是坐标的函数）。**禁止**：依赖墙钟、kernel 耗时、可用显存、host 负载。
>
> 若实现动态 $K$，`I-021` 的探测器（$\forall K$ 位级）自动覆盖它 —— 因为动态 $K$ 产生的是 $K$ 序列，而位级不变性对任意切分成立。

这比我原来打算写的"引入动态 $K$ ⇒ 全部位级断言失效"好得多，而且**它是免费的**：我不需要为动态 $K$ 做任何额外设计，只需要保证五根柱子。这是"地基做对了，上层自由度自动获得"的一个具体实例，值得在 §3 开头点出来作为投资回报的说明。

# S1 — 接受，禁令改为作用域限定

全集禁令会误伤看门狗、IO 超时重试、性能计数器。正确形式：

```
§3.3 时钟禁令(作用域限定)

结果路径 = 任何输出能影响 x/v/λ/state/接受判据/落库数值的代码
  device : 全部内核
  host   : HREX 判据、barostat 判据、ALF 更新、checkpoint 写入内容、
           u_kn 落库、回滚决策
  → 禁止读取任何时钟(墙钟、clock64()、event elapsed time)

豁免层 = 调度器、异步 IO、日志、性能剖析、看门狗、超时重试
  → 可读时钟,但禁止向结果路径回传时间戳或任何时间派生量

CI 静态检查
  ① 结果路径文件白名单 + 时钟 API 黑名单(clock64, chrono, cudaEventElapsedTime, time, gettimeofday)
  ② 豁免层 → 结果路径的数据流检查:豁免层的返回值不得进入结果路径的函数参数
```

② 比 ① 难做但更重要，因为真实的泄漏路径不是"结果路径直接读时钟"，而是"调度器算了个超时决定，把它变成一个 `n_steps` 传给引擎"。这类泄漏在 ① 下完全不可见。

一个具体的危险实例我要提前钉住：**调度器的抢占**。如果抢占时机由墙钟决定（"跑满 2 小时就 checkpoint 退出"），而 checkpoint 落在**任意步**，那么恢复后的轨迹依赖抢占时机 ⇒ 违反 m2（checkpoint/restart ≡ 连续运行）。

**修法**：抢占只允许发生在**窗口边界**，且 checkpoint 内容与"在该步主动 checkpoint"位级相同。墙钟决定的是"在下一个窗口边界退出"，而窗口边界是模拟状态的函数。**时间只能影响"何时停"，不能影响"停在哪"** —— 后者必须由步数决定。

这一条登记为 `I-022`（构造/地板，探测器 = 在随机步数处抢占 + 恢复，与连续运行位级对比），并且它是 m2 的实现条件，我此前只写了 m2 的断言没写它的成立条件。

一个观察作为收尾，也是我这六轮唯一想留下的方法论结论：**S3 的价值不在于修正了一个答案，而在于它演示了"问题问错"这一类失败。** 我问的是二选一（时序依赖 vs 登记项），评审给的是"两个都不是，真正的支点在第三处（masking）"。前五轮抓的是我写错的东西，S3 抓的是**我没想到要看的地方**，而它之所以能抓到，是因为评审去追了"K 自由"这个性质**依赖什么**，而不是回答我问的"K 是不是危险"。

这对应到 spec 的做法上：**不变量适用域表的正确用法是自下而上追依赖，不是自上而下列风险。** 我一直在写"这条断言在什么条件下失效"（自上而下），而 S3 示范的是"这个自由度由哪些柱支撑"（自下而上）。上面那张"下游自由度"表是按后者写的，它比我此前所有的失效触发列表都更有信息量 —— 因为它把柱子和收益连起来了，而失效列表只告诉你别碰什么。
