# opus5.md 规格评审

**评审对象**:`docs/opus5.md` v1.0(2026-08-25,M0 启动基线)
**评审性质**:批判性技术评审。只列实质问题;设计优点(副本最内层、定点累加、交换 λ、维里移出关键路径、雷区清单)不再复述。

---

## Critical

### C1. CUDA Graph 重放窗口内,邻居列表有效性无人保证(§7 × §5.2)

规格的主循环是:

```
rebuild_neighborlist()   # host,只在窗口边界
graph_replay(K steps)    # K = 20–50,窗口内无法分支
```

重建判据 `max|x − x_ref| > skin/2` 只在 graph 重放**之间**检查。但 graph 内无法数据依赖分支,意味着 K=20–50 步(40–100 fs)内列表必须保持有效,而**没有任何机制保证这一点**。

定量:skin = 0.25 nm ⇒ 允许漂移预算 0.125 nm。O 原子 300K 单分量 1σ 弹道漂移 ≈ 0.039 nm/100fs;在 ~3×10⁶ 原子·副本 的系综里,5σ 尾部 ≈ **0.20 nm > 0.125 nm**。也就是说 K=50 时,稀有但非零概率地,某粒子在一个重放窗口内跑出 skin/2 → **静默漏对**(不崩、不报警,力错一点点——正是本 spec 自己最警惕的那类误差)。

GROMACS 的 Verlet buffer 就是为这个问题存在的:buffer 大小由 **nstlist 整个间隔**的漂移估计决定,而不是瞬时漂移。本 spec 把判据写成了瞬时形式。

**建议**:① skin 预算显式拆成「检查阈值 + 窗口安全余量」,余量由 K 步最大漂移的实测分布定;② 在积分 kernel 里每步做一次 max-displacement 归约(几乎免费),写 device flag,重放结束后 host 检查,若触发则该窗口作废重来或缩短 K;③ M2(graph ≡ K×step)的测试轨迹必须包含「窗口中段触发重建」的用例,否则这个 gate 测不到它要防的东西。

### C2. M1「位级等价」与批量 cuFFT 冲突(§11.2 × §5.1)

M1 要求 R 副本批量 ≡ R 次 R=1 串行,**位级、零容差**。但 §5.1 规定倒空间用「一次批量 cuFFT」。cuFFT 不保证不同 batch 数/不同 plan 配置之间结果位级一致——批量 48 路的 FFT kernel 与单路 FFT 的归约顺序、twiddle 路径可以不同,末位 ulp 级差异会直接打碎 M1,而 PME 能量混在总能量里,没有哪个量能豁免。

**建议**:二选一,写进 spec——(a) 倒空间永远按 per-replica plan 逐副本计算(M1 保位级,牺牲批量 FFT 效率);或 (b) M1 拆成两层:直空间/键合/积分位级等价,含倒空间的量放宽到 rel < 1e-12,并说明为什么这个放宽不影响任何下游断言(u_kn 容差、A1 的 1e-10 都远高于 1e-12)。现在的写法是两条规格各自合理、合在一起不可满足。

### C3. u_kn「3–5× 单次能量」的成本主张缺了它唯一成立的算法(§8.3)

「同一构象在 48 个 λ 下算能量,复用邻居列表与距离,成本 3–5× 而非 R² 倍」——这对**直空间**成立(距离算一次,λ 循环只换参数)。但**倒空间不成立**:各 λ 电荷不同 ⇒ ρ(k) 不同 ⇒ 朴素实现是每个构象 × 48 次电荷铺展 + 48 次 FFT,PME 恰好是 u_kn 的主导成本,3–5× 直接变 20–40×。

这条主张其实**有救**,而且救法就藏在 spec 自己的雷区 #1 里:倒空间能量对电荷是二次型。电荷线性插值 q(λ)=q₀+λΔq ⇒ ρ_λ(k)=ρ₀(k)+λΔρ(k) ⇒

E_recip(λ) = Σ_k S(k)|ρ₀|² + 2λ·Re Σ_k S(k)ρ₀*Δρ + λ²·Σ_k S(k)|Δρ|²

每个构象只需 **2 次铺展 + 2 次 forward FFT + 3 次网格归约**,之后全体 λ 的能量与 ∂E/∂λ 都是解析求值。多分量 λ(C 个电荷微扰分量)时是 C(C+1)/2 个交叉项,实践中 C 很小。这样 3–5× 才成立。

**建议**:把该算法(或别的什么算法)显式写进 §8.3。现在 spec 在最值钱的一句性能主张后面没有算法,而这里同时是雷区 #1 的案发现场——自能项、排除修正也都是 λ 的二次型,必须一起进同一个推导,不能分三次写对。

### C4. 5–10× 批量加速的账目对不上(§10)

spec 自己列的红利:邻居列表摊薄 15–25% + 参数广播 5–10% + launch 摊薄 10–30% + 「occupancy 改善」(未量化)。前三项合计移除单步时间的 30–65% ⇒ 加速上限 ~1.4–2.9×。要到 5×(M2 验收线)乃至 10×,**缺口全部压在未量化的 occupancy 一项上**——即隐含假设「单个 60k 原子 fp64 副本远未吃满 A100」。这个假设可能为真(60k 原子 + PME + 约束 + 积分, kernel 间有大量未饱和段),但它是整个 M2 验收标准的承重墙,却没有任何测量计划。

**建议**:E0 增加一项——单副本 fp64 的 SM 占用率/吞吐实测(nsight),把「occupancy 改善」从修辞变成带数字的假设;否则 M2 的 <4× red flag / >10× 优秀这条线本身无法证伪:达不到时你无法区分「批量设计错了」与「基线本来就接近饱和」。

## Major

### M-a. R=48 编译期固定 vs 性能评估规则自相矛盾(§2.1 × §10)

§2.1:「R 编译期固定为 48,padding 到 8 的倍数」(48 本来就是 8 的倍数,padding 一句只有在 R 可变时才有意义)。§10 评估规则 1:「benchmark 参数随机化(……λ 窗口数、副本数)」。§11.2 M4:「结果与副本数 R 无关」。三处都在说 R 可变,只有 §2.1 说 R 焊死。

**建议**:改成「R 是模板参数,实例化 {1, 8, 48, …} 离散集合,生产二进制固定 R=48」,M4 与 benchmark 随机化在实例化集合内成立。一句话能修好,但现在四段文字互不相容。

### M-b. A2 把核心语义外包给了 openmmtools 的内部行为(§11.1)

A2 要求与 `AbsoluteAlchemicalFactory` 全 u_kn 层对齐到 rel < 1e-9。这不是一个测试 harness 问题,而是**把软核函数形式、1-4 exception 处理、alchemical PME 处理的精确语义,以「行为匹配第三方库内部实现」的方式定义**。具体风险:

- openmmtools 在 PME + annihilate electrostatics 下默认直接报错,必须用非默认的 `alchemical_pme_treatment='direct-space'` 之类选项——A2 的配置本身就是一份需要钉死的规格,spec 只写了软核 α/a/b/c 四个数;
- 炼金原子的 1-4 exception 在 openmmtools 里有特定处理(是否软核化、在哪个 Custom force 里),与朴素 NonbondedForce 语义不同;
- 「行为匹配」意味着 openmmtools 升级或换选项,你的语义跟着漂。

**建议**:在 spec 里冻结炼金项的**完整解析定义**(软核公式、exception 缩放表、PME 三处的 λ 缩放公式),A2 降级为「该定义的一个外部见证」。这正是雷区 #6 的正确处置方式:harness 对齐的是公式,不是黑盒行为。

### M-c. LJ 长尾色散修正 / switch 函数 / LJPME 全部未指定(§1.1 / §5)

`NonbondedForce(PME + 排除 + 1-4 缩放)` 只说了静电侧。LJ 侧:cutoff 之后是解析尾部修正还是 LJPME?有没有 switch 函数?OpenMM 的 `useDispersionCorrection` 默认开启且**随 λ 变**(被 decouple 的原子对尾部积分有贡献)。这一项不进规格,A1 的 1e-10 对不上,ΔG 也会有系统性偏移(溶剂化自由能对尾部修正敏感是已知结果)。

**建议**:§5 加一小节写死:cutoff 值、switch 形式(或无)、尾部修正公式及其 λ 依赖,A1/A2 断言覆盖它。

### M-d. ∂U/∂λ 没有独立 oracle(§4.2 / §11)

∂U/∂λ 全部由 IR 自动微分产生,而验证矩阵里: M9 只查端点、A3 的 λ 路径无关性只查积分后的 ΔG、A2 只查能量不查导数。**自动微分的接线错误(某个 ParamExpr 的 ∂θ/∂λ 漏乘、λ 分量错位)可以穿过全部现有 gate**,只要端点能量对、总 ΔG 碰巧对。

**建议**:M1 里程碑加一条廉价且强力的 oracle:对每个 λ 分量做中心差分(±δ 两次能量求值,f64 下 rel 1e-6 易达),与解析 ∂U/∂λ 逐分量断言。不需要新内核,ingest 层就能做。雷区 #12(u_kl 索引错位)的注入测试也该覆盖 dU/dλ 向量而不仅是标量能量。

### M-e. MC barostat 在 48 副本体系上的语义未定义(§6.4)

「预平衡:MC barostat;生产:NVT,体积取预平衡 NPT 平均后固定」——预平衡跑的是哪个副本?R=1 单副本平衡完再复制成 48?还是 48 副本共用一个 barostat(用谁的能量做接受判据)?另外,不同 λ 态的平衡体积本来不同,固定单一盒体积对所有 λ 是个近似——对 RBFE 配合物腿通常无害,但 spec 应明说这是个近似并给出适用边界(比如净电荷微扰时不成立,与雷区 #3/#4 联动)。

**建议**:写清预平衡协议(R=1、λ=某端点 or 全 λ 各平衡?),并把「单体积近似」登记为条件性成立知识(minefield 005 的同类)。

## 总体判断

这份 spec 的骨架是对的:范围切割、确定性优先、雷区意识、E0 前置实验、把维里和 NPT 移出关键路径,都是少见的老练决策。**最可能翻车的地方不在物理,而在三处「叙事与机制的接缝」**:

1. **确定性叙事 vs cuFFT 批量**(C2)——位级等价是全部变形测试的地基,地基里埋了一个未经论证的第三方库行为假设;
2. **性能叙事 vs 未测量的 occupancy 假设**(C4)——M2 验收线压在一个没量过数的机制上;
3. **「共享/批量/零成本」叙事 vs 窗口有效性**(C1)——graph 重放窗口内的邻居列表,是「共享列表是超集」这个不变量唯一可能静默失效的地方,而它恰恰发生在两次 host 检查之间。

共同模式:这份 spec 对自己**写了下来的**雷区防守严密,漏洞集中在**两个正确机制拼接处的隐含前提**。建议 M0 启动前把 C1–C4 的处置写回 spec,M-a–M-e 至少给出显式决策。

# 第二轮:patch(`opus5_patch1.md`)复核 + 五模型 Fusion 交叉评审

## A. patch 复核:可以合入,但合入前修三处

patch 对 C1–C4 的接受与方案(三层列表防护、M1 分层、二次型展开、E0a/b/c + 两段式 M2)都对;§14 量化断言溯源表是全场最有价值的修改,根因诊断(增量写 spec、引入新机制不回查既有量化断言)准确。但:

1. **M-e 阶段 3 引入了新接缝(最严重)**:「R=48 每副本独立 MC barostat」⇒ 每副本盒矢量不同 ⇒ 共享邻居列表的物理前提在预平衡期不成立;「ABFE 用 per-replica ⟨V_λ⟩」⇒ 生产期共享盒也不成立,直接推翻 §1.2 砍 NPT 的整个推理。要么 ABFE 也单体积(推荐,配体偏摩尔体积效应用雷区 #13 框住),要么明说 ABFE 放弃共享列表红利并量化代价。预平衡期的 per-replica 盒/列表是一条新代码路径(~14 GB 显存,装得下,但与「单一数据布局」叙事冲突),必须显式决策。
2. **M5 从来不该在位级表**(第一轮双漏,patch 把分层追到 M4 但没追到 M5):PME 网格各向异性使任意平移/旋转只有 ~1e-4 级一致性;只有格矢整数倍平移位级成立。M5 整体移入 11.3,拆三档。
3. **patch 自己立的 §14 第一处就没贯彻**:C1 节「list 比原设计大约 30%」无出处——skin 总量不变时列表大小不变,变的是重建频率(阈值 0.125→0.05,扩散主导下频率涨 ~6×);且 d_thresh=0.05 + s_window=0.15 的角落情形余量恰好为零,预算公式需要显式 margin 项。

小错:C1② 的 checkpoint 算术应为 x+v=138 MB(非 276,m1 节自己写对了);m8 回滚 checkpoint 不需要存 F(回滚是稀有事件,重算一次力即可);s_window 应声明为「性能参数非正确性参数」,极值统计上「实测 max+50%」系统性低估尾部,正确性由 flag 回滚机制兜底。

## B. Fusion 五模型评审:patch 未覆盖的新发现

### Critical

**B1. 电荷铺展的 run-to-run 确定性 —— patch 的 C2 方案有前提漏洞。** M1b 分层解决的是「batch 48 vs batch 1」的跨配置一致性,但更深一层:若电荷铺展用 fp64 `atomicAdd` 入网格,**单次运行自身就没有 run-to-run 位级确定性**(FFT 输入随线程调度漂移),patch 新立的 M15(同 plan 重复执行位级相同)会直接红。修复只有两条路:铺展也走定点网格累加(int64 网格,与 Q24.40 同族),或固定序分段归约。**这是「确定性叙事」能不能成立的真正地基,必须在 M0 前拍板。**

**B2. MC barostat 的联合系综语义完全未定义 —— 比 patch 处理的更深。** 48 个不同 λ 的 Hamiltonian 共享一次体积移动时:Metropolis 判据里的 ΔU 是 Σ_r ΔU_r、单副本、还是端点?雅可比是 N·lnV 还是 48N·lnV?**任何一种选择都不等于「每副本独立 NPT」**,平稳分布各不相同。且:坐标缩放必须按分子质心/刚性水整体缩放,否则 SETTLE 约束被体积移动瞬间破坏;体积变化 ⇒ PME 网格间距/Ewald 参数/色散修正全变 ⇒ 静态 graph 要重新 capture(§7 的「形状完全静态」在预平衡期不成立)。「MC barostat 正确性仅依赖能量正确性」不成立——还依赖雅可比、缩放约定、体积策略。这类错是**分布错而非能量错,A1–A5 天然测不到**,必须补系综级验证(NPT 体积分布对照)。与 A 节第 1 条合并:barostat 需要一整章推导,不是一段协议。

**B3. §7 与 §10 的步长数字互相矛盾,差一个数量级。** §7 说 48 副本单步内核「数百微秒」;§10「每副本 30–70 ns/day @ 2 fs」反推单步 2.5–5.8 ms。若步时间是后者,则「数十 kernel × 5–10 μs launch 占 10–30%」也不成立(只有 2–8%)。这个对撞证明目前没有任何 bottom-up 性能账——并入 C4:E0b 之前先交逐部件 roofline(direct/spread/FFT/约束/积分各列 FLOP、字节、占比),M2 门槛对照预测区间而非拍出的 5×。

| B8 | **Gibbs 全对交换消灭了「2 个独立重复」的语义** | 两个 repeat 耦合成单一 48 副本马尔可夫网络后,不再是独立链,基于独立重复一致性的收敛诊断和调度器杀任务逻辑全部失效。要么 2×24 两个独立交换网络,要么定义新收敛指标(往返率、λ 轨迹 τ_int、bootstrapped MBAR 不确定度)并改掉「独立重复」措辞 |
| B9 | **交换判据与 u_kn 计算频率未绑定 ⇒ 细致平衡破口** | §8.2 每 50–100 步交换,§8.3 每 M 步算 u_kn;若交换判据用陈旧能量,细致平衡被破坏。强制「交换步 ≡ 能量计算步」,交换只算当前所需能量,全矩阵可降频 |
| B10 | **Q24.40 范围论证不足 + release 关溢出检查是「可复现的静默反号力」** | ±8.4e6 对平衡轨迹充裕,对带 clash 的未最小化初构不足(FEP 输入常态);位级确定系统里溢出会可复现地传播且全部等价断言照常通过。要求:最坏力显式推导(软核力上限+最小允许距离)×安全因子;ingest 加 max-force 门控;溢出改饱和+粘滞标志,replay 边界检查,**release 也保留**。另:「沿用 Amber SPFP 定标」需核实——SPFP 是分力项定标的 int64 累加,不是单一 Q24.40;Q34.30 含不含符号位未定义 |
| B11 | **A1/A2 纯相对容差缺 abs 下限** | 湮灭端点/力近零处分母发散,rel 容差不稳定。改 abs+rel 双门并给出 abs 下限 |
| B12 | **系综级 HREX 验证缺失** | 交换开/关下每 λ 边缘分布一致、接受率 vs 理论重叠、往返时间分布、λ 占有率 vs MBAR 预测。注入测试只测 plumbing 不测 sampling(patch 的 A7 只覆盖接受率一项) |
| B13 | **E0 的代理不可移植** | OpenMM mixed vs double 只是下界;真正要决策的是「自研 f32+定点 vs 全 f64」。补同体系同列表的内核级微基准(direct/spread/积分分项)再拍板 |

### Minor(批量)

- 步长语义:§10 靶子按 2 fs,§6.3 用 HMR 的意义是 4 fs——若生产仍 2 fs 则 HMR 白付柔性键代价,若 4 fs 则所有 ns/day 靶子翻倍。需明确生产步长决策点
- host 侧 RNG(HREX/barostat/ALF 判据)未纳入 counter-based 政策,跨配置可复现性在交换判据层面破裂
- graph 内 step 计数器注入机制未定(`cudaGraphExecKernelNodeSetParams` vs device 计数器),影响 M2 与 checkpoint 实现路径
- 128³ 网格的盒尺寸选择规则未写,换体系即破坏「静态形状」假设
- REST2 悬空:λ 向量声明含 β 分量但力项清单没有 REST2 实现,要么补要么删
- ingest 前置条件未声明:未最小化体系第一天就触发 Q24.40 溢出(与 B10 联动)
- 「传统交换间隔 ≥1000 步受通信限制」不准确:更根本的约束是能量去相关时间,100–200 fs 后收益饱和,应以往返率实测为准
- 「参数读取为广播」机制描述不准:跨副本广播的是基准参数,λ 相关参数是合并读取
- `pme_recip` 降 f32 时 Madelung 只覆盖静态晶格,须声明放弃哪些 M 断言并配动态 oracle

## C. Fusion 的一处误判(纠偏)

「CustomNonbondedForce 是 A2 的阻塞性依赖」——**不成立**:A2 的 openmmtools 体系在外部 OpenMM 里跑(零动力学、固定构象),引擎 ingest 的是未炼金化的物理体系,IR 不需要为 A2 支持 CustomForce。但「尽早界定表达式语义子集 + M0 用真实 openmmtools 输出做 ingest 冒烟 + 翻译层自身需要 oracle」仍然成立,开放项 2 的优先级该提。

## D. 合并后的「M0 之前必做」清单

patch 的启动顺序 + Fusion 增量,按依赖排序:

1. **E0 全套**:E0a(OpenMM mixed/double)+ E0b(单副本 Nsight 剖析)+ E0c(N 标度)+ **cuFFT batch×plan 位差扫描**(B1/B2 前提)+ 内核级 f32/f64 微基准(B13)+ 逐部件 roofline(B3)。C4 结论可能推翻批量架构价值假设,最先做
2. **§4.6 炼金术解析定义**:先解决 B4 的 (1−λ)² vs b=1 矛盾,再冻结软核/exception/PME 三处/调度;§5.3 LJ 侧(cutoff/switch/尾部修正及其 λ、1/V 依赖)
3. **确定性专章**:铺展定点化或固定序归约(B1)、RNG 稳定 atom ID + host RNG 政策(B5)、CCMA 固定形状(B6)、plan manifest 哈希、**M 系列重排为三档**(位级档:键合/实空间/积分/格矢平移;倒空间容差档:PME/任意平移/旋转,容差实测定;统计档:分布类断言)

5. **C1 三层机制落地** + §14 溯源表回填所有既有数字(含「30%」这个第一个练习)

## E. 两轮合并后的总体判断

第一轮判「接缝处翻车」,Fusion 把它推进了一层:**这份 spec 最大的系统性风险是把条件性成立的东西写成了无条件成立**——位级确定性(对倒空间、RNG、CCMA 不成立)、「3–5× u_kn」(只对二次型分解成立)、「零成本 HREX」(只在 state↔slot 归属正确定义后成立)、「5–10× 批量」(只在 occupancy 假设成立后成立)、「MC barostat 只依赖能量正确性」(不成立)。Patch 的流程修复(§14 溯源表)是对的药,但 B1–B3 说明**还有三处地基级的决定没做**:铺展确定性、barostat 系综语义、bottom-up 性能账。这三件事不拍板,M0 的「慢的 O(N²) fp64 直算定义语义」会定义出一套上了 GPU 就兑现不了的语义。

# 第三轮:patch2 复核(2026-08-25)

**总体:三轮中最强。Part 1 roofline、A.1 的 R=1 串行预平衡(用设计选择消解 B2 而非推导)、B1 定点铺展、B7 slot/state 表、B8 的 2×24 独立网络、M0「结构同构」修正——全部正确且有价值。B 系列 13 条处置无一错误。但 patch2 在自己最得意的 Part 1 里引入了一处新的内部矛盾,且 4 fs 决策触发了它自己 §14 表里的失效条件而没有回查——§14 的第二次实战检验,第二次没通过。**

## P1(major):Part 1 的 roofline 与「修正后估计」表互相矛盾——红利不是 1.2–1.4×,而是 ~2–4×

patch2 自己的两组数字:

- roofline:批量 48 副本 @ 40–50% peak ⇒ 15–18 ms/步 ⇒ 每副本 9.6–11.5 ns/day ⇒ **总吞吐 460–550 ns/day**
- §10 参考:单副本 fp64 = 130–250 ns/day
- 两者相除:批量红利 = **1.8–4.3×**

但同一份 patch 的「修正后估计」表结论是「合计 1.2–1.4×,occupancy ≈ 0(直空间已饱和)」。**这两段互相矛盾。** 错误的根源是结论③的推理:「1.18×10⁹ 对/步意味着 6912 个 fp64 lane 全程有活干 ⇒ 没有 occupancy 头寸可捡」——这论证的是**批量**能喂饱机器,而红利恰恰是相对于**串行基线**定义的。用 §10 自己的数字反推:单副本 130–250 ns/day ⇒ 0.7–1.3 ms/步,单步 ~2.1×10⁹ FLOP(直空间+PME)⇒ **单副本只跑在 16–31% of fp64 peak**。批量把效率从 ~16–31% 推到 40–50%,这个效率恢复**就是红利的主体**,它不是零——它就是 C4 里那个「未量化的 occupancy 假设」的量化形态。

修正后的正确表述:

$$
\text{批量红利} = \underbrace{\frac{\eta_{\text{batch}}}{\eta_{\text{serial}}}}_{\text{效率恢复,}\sim 1.5\text{–}2.7\times} \times \underbrace{f_{\text{amortize}}}_{\text{列表/参数/launch,}\sim 1.2\times} \;\approx\; 2\text{–}3\times
$$

连带修正三处:

1. **M2 验收线**不该是「≥1.2×」——那是把红利只算成时间移除的结果。M2 的正确形式:**E0b 实测单副本与批量的 achieved % of fp64 peak,预测区间 = 效率比 × 摊薄项,验收 = 落在区间内**。patch2 的「roofline 足以否掉 5×」对(靶子超过 100% peak 的 24 ns/day/副本上限,死透了);但「否掉 5×」不等于「红利只有 1.2×」。
2. **B13 的相对比较错了**:「f32 直空间 ~2× 比批量红利大得多」用的是错误的 1.2–1.4×。用修正后的 2–3×,f32 杠杆(~1.4×,2:1 只作用于计算受限的直空间部分)与批量红利**同量级且相乘**,开放项 1 的措辞应相应调整。
3. **§14 溯源表第 4 行**的值(1.2–1.4×)改为预测区间待定(E0b),失效触发条件加上「η_serial 实测与 §10 参考值不符」。

## P2(major):4 fs 决策触发了 §14 第 5 行自己声明的失效条件,但没有回查

patch2 第五部分决定「生产 4 fs + HMR」,§10 数字翻倍。但 A.3 的 skin 预算($s_{\text{window}} = 0.12$)是按 **2 fs × K=50 = 100 fs 窗口**校准的;4 fs 下同样的 K 覆盖 200 fs,窗口漂移近似翻倍(弹道)或 ×√2(扩散)。§14 第 5 行的失效触发条件白纸黑字写着「改步长」——**这是 §14 的第二次实战检验,它又没被执行。**

处置二选一(写进 spec):生产 4 fs 时 K 减半(20–25),或 $s_{\text{window}}$ 按 200 fs 窗口重校准、skin 重算。注意这又会反过来影响 P1 的对数与步时间——一处改、处处查,这正是溯源表存在的意义。

## P3(minor):roofline 缺 PME/约束/积分(已自认 TODO,但量级要心里有数)

48 路 $128^3$ fp64 FFT(正+逆)≈ 2.1×10¹⁰ FLOP,铺展/回插 ≈ 7×10⁹,合计在直空间 7.1×10¹⁰ 之上 **+40% 左右**,且 FFT 的 achieved-%-of-peak 低于直空间对循环。单步时间修正到 ~20–26 ms,每副本(4 fs)13–17 ns/day。结论不变(原靶子死得更透),但 §14 第 2–4 行在补齐前应标记 provisional。另外 E0b 必须**分开测** FFT 与直空间的效率,因为两者的 occupancy 故事完全不同——这恰好是 P1 的预测区间需要的输入。

## P4(minor):CUDA Graph 动机改写用词不当

改为「确定性与代码简洁」——graph 不提供任何确定性(确定性来自定点累加 + counter RNG + 固定 plan)。graph 的真实价值:(a) launch 开销 1.5–3%;(b)**它强制了「K 步窗口」的显式边界,而 C1 的回滚机制、M2 的等价断言、B10 的粘滞标志检查点全都挂在这个边界上**。后者才是结构性的理由,建议照此写。

## P5(minor):M9 的参照系构造需要补一句

生产决定用柔性微扰键 + HMR 后,M9「λ 端点 vs 对应的非炼金术 System」的参照 System **必须用同样的 HMR 与柔性键设置**来构建,否则 1e-9 对不上(约束 vs 柔性键的势能面不同)。一行话,但不写就会有人拿默认设置的 OpenMM System 去对。

## 用户决策已到达:ABFE 占比 ≈ 0

对应 patch2 三情形表的**第一种(纯 RBFE)**。解除阻塞的连锁动作:

1. §6.4 与系综语义专章**可以定稿**:R=1 串行预平衡 + 全局单体积,引擎永不存在多副本 barostat;「盒矢量任何时刻全副本相同」成为无条件运行时断言
2. §0 目标负载的「RBFE / ABFE」改为「RBFE;ABFE 为 backlog 低频路径」
3. ABFE 偶发需求走**独立作业路径**(无跨 λ HREX,每窗口独立平衡),牺牲明确记录
4. 雷区 #7(限制势标准态修正)保留条目但 enforcement 标记 deferred,与 ABFE 路径同批激活
5. 调度器/EVSI 按 RBFE 配体对优化

## 本轮确认无误的重点处置(不再复核)

B1 定点铺展(Q16.48 网格 805 MB 等价替换、§3.3 归约政策 CI 可检)· A.1 预平衡成本核算(0.4 GPU-hour ≈ 1.3%,算术已复核)· B4 冻结 a=1,b=1,c=6,α=0.5,先组合后软核,方向 spec→A2 · B5 稳定 atom ID + M6 降级单点 + M6b · B6 CCMA 固定迭代数 · B7 slot/state 归属表(RNG→slot 是关键行)· B8 2×24 网络 + 合并 MBAR 解 · B9 交换步≡能量步 · B10 饱和+粘滞标志+ingest max-force 门控(删 Amber 归属改纯推导,对)· B11 abs+rel 双门 · B12 A7a–d(A7b 边缘分布 KS 检验是核心)· M0 结构同构(参考实现必须含 PME 网格 + 定点累加 + R=1 barostat——补一条:参考实现的 PME α/网格/样条阶数必须与生产钉死一致,它是 M1b/M15 基线的生成器)

## 三轮后的元观察

patch2 的自我诊断(「同一个认知习惯的 25 次显形」)是对的,而 P1/P2 说明这个习惯不会因为意识到了就自动消失——**P1 是「写下 roofline 后没有让它穿过同文档的所有相关数字」,P2 是「改了步长后没有执行自己声明的失效触发」**。两轮 patch 各抓到对方一层,这恰好是双红队/多轮评审存在的理由。§14 的两张表(量化溯源 + 不变量适用域)现在是 spec 里最重要的章节,建议把它从附录提到正文,并把「任何 patch 必须声明它触发了哪些表行」写成提交流程的一部分——因为这三轮证明,**人(包括写表的人自己)不会自觉执行这张表,只有流程会。**

# 第四轮:patch3 复核 + A100 实测(2026-08-26)

## 实测部分(A100 80GB PCIe,driver 580.105.08 / CUDA 13.0,cuFFT 12.x 经 cuPy 14.2)

测试机当时被 vLLM(70 GB)+ Desmond 占满(100% util)。**位级测试不受竞争影响,照常有效;时序类测试(E0a/E0b/E0d)无效**,脚本已备在远程 `/root/`(e0a 自带 util 门卫,GPU 占用 >20% 自动拒跑),OpenMM 已装,等空闲窗口。

### M-E0e:cuFFT 位差扫描 —— C2 的前提在本栈上不成立(好消息)

| 测试 | 结果 |
|---|---|
| c2c fwd,64³/128³,batch {1,4,8,48} 两两对比 | **全部位级相同**(0 差异元素) |
| r2c fwd / c2r inv,96³/100³/120³/128³,batch {1,24} | **全部位级相同**(含非 2 幂尺寸) |
| 同 plan 重复执行 / in-place vs out-of-place | 位级相同 |

结论:**此栈上 cuFFT 的 per-transform 数值与 batch 数无关**(batch 只是跨 transform 的并行维度)。M1 的位级等价**有可能整体保住**,M1a/M1b 分层可从常态降级为保险条款。但这是实测性质不是合同性质 ⇒ 处置:① plan manifest 哈希照旧;② E0e 改编译器/驱动/架构变更时的常驻 CI 回归;③ 预期模式 = M1b 永不触发。**C2 从「已证矛盾」降级为「实测无差、常驻监护」。**

### M-B1:fp64 atomic 铺展 —— B1 前提成立且比声称的更强(坏消息变硬约束)

模拟 PME 铺展(60k 原子 × 64 网格点 scatter 入 128³ 网格):

| 测试 | 结果 |
|---|---|
| fp64 atomicAdd,block=128 vs 512 | **DIFF**,87342/2.1M 元素,maxrel 1.6×10⁻¹¹ |
| fp64 atomicAdd,**同配置 run-to-run ×5** | **全部 DIFF**,~1.5×10⁴/2.1M 元素,maxrel ~10⁻¹²–10⁻¹³ |
| int64 Q16.48 定点,block=128 vs 512 | **位级相同**(0 差异) |
| 定点 vs fp64 数值一致性 | 差异在 fp64 自身累加噪声量级(相消严重网格点 maxrel 1.7×10⁻⁸,绝对误差 ~10⁻¹³)——**定点和是精确参考** |

结论:fp64 atomic 铺展**连 run-to-run 位级稳定都没有**(K2),不只是跨配置问题。patch2 的定点网格方案(§3.3)从「增强」升级为「M0 开工前置」。注:run-to-run DIFF 在 GPU 有竞争下测得;空闲机上同配置可能碰巧一致,但原子加顺序从来没有合同保证——竞争只是让无保证变得可见。

### 附带发现(测试自身的一课)

r2c 测试第一版报过 maxrel=2.0 的「DIFF」,原因是漏写 `axes=(1,2,3)`,batch 轴被一起变换——**不是 cuFFT 的错,是测试的错**。一个连测试作者都会犯的 axes 错误,如果发生在引擎里就是雷区 #12 型索引错位。这正是为什么断言要钉在明确语义上、注入测试要覆盖索引维度。
