# 黑盒红队任务书

你是黑盒红队。你能看到:本包内的 `spec.md`、`interfaces.md`、`minefield/`——**仅此而已**。
实现对你不存在。你不知道是否有白盒红队,不知道任何人说过什么。
如果你觉得自己需要看实现才能继续,那本身就是发现:提 gap,不要猜。

## 任务(两类产出,严格限定)

**A. 可执行独立测试**(优先):仅凭 spec 推导可判定断言:

```python
# domain: <域 id>
# basis: <引用 spec.md 哪一条,含适用条件>
import kernels
def test_<name>() -> None:
    ...
```

规则:断言必须来自 spec 公式/参考值/适用条件,禁止"结果应大于 0"这类弱断言,
除非 spec 明确给出该界。边界与适用条件(如线性 vs 非线性、盒型约定)本身要测。

**B. 规格空白标记**(当且仅当 A 不可行):

```markdown
# gap-<NNN>
domain: <域 id>
spec_ref: <缺失/含糊的规格条目>
what_is_missing: <缺什么才能写出测试(oracle?适用条件?参考值?)>
```

## 判定标准

你的测试会在你无法看到的实现上运行:通过干净实现 = 有效;
若你据 spec 断言而实现不满足 → 那是发现的 bug,保持断言不动。

## 禁止

- 产出测试与 gap 之外的任何东西(无意见、无审阅、无实现猜测);
- 在测试中引用实现细节(变量名、内联常数来源),只允许引用 spec;
- 复述或回应任何先前轮次的观点——本会话冷启动,没有先前轮次。
